# DENTE Dental CRM — On-Premises Installer & Deployment Hub

Центральное руководство по локальному развертыванию, сетевой конфигурации и администрированию DENTE Dental CRM в стоматологических клиниках.

Документ описывает установку и эксплуатацию платформы на серверах клиники под управлением **macOS** (Mac mini / MacBook / iMac) и **Windows** (ПК / Рабочая станция / Windows Server).

---

## 1. Архитектурная концепция локального развертывания

DENTE Dental CRM спроектирована для работы непосредственно внутри клиники с обеспечением **100% автономности от внешних облаков**:
- **Локальный суверенитет данных**: Все медицинские карты (Форма 043/у), рентгеновские снимки (визиограф, ортопантомограммы, КЛКТ DICOM) и финансовые чеки хранятся локально на сервере клиники в соответствии с требованиями 152-ФЗ.
- **Работа при обрыве интернета**: Регистратура, врачи у кресел и касса продолжают функционировать в штатном режиме без задержек при падении внешнего интернет-канала.
- **Работа в Session 0 / Daemon Mode**: Серверные службы запускаются на системном уровне до входа пользователя в операционную систему и продолжают работать при блокировке экрана или смене сеанса пользователя.
- **Автоматическое устранение последствий блэкаутов**: Скрипты предварительной проверки (Preflight) автоматически устраняют зависшие lock-файлы `postmaster.pid` после внезапного обесточивания клиники.
- **Разрешение конфликтов портов**: При совпадении порта PostgreSQL 5432 с внешними сервисами (например, базами 1С:Предприятие) система автоматически переключается на резервный порт **5438** (`D-E-N-T-E`).

## 2. Матрица сетевых портов и протоколов

Для корректной работы всех рабочих станций, планшетов у кресел и фискального оборудования в локальной сети клиники используются следующие порты:

| Порт | Протокол | Назначение | Область видимости | Примечание |
| :--- | :---: | :--- | :--- | :--- |
| **4000** | TCP | Fastify REST API & SPA Web Client | LAN / Localhost | Основная точка входа для браузеров и планшетов |
| **4100** | TCP | WebSocket Event Broker | LAN / Localhost | Шина мгновенной синхронизации расписания и статусов |
| **5432** | TCP | PostgreSQL 18 Primary Port | Localhost (127.0.0.1) | Основной порт СУБД для локального ядра |
| **5438** | TCP | PostgreSQL 18 Fallback Port | Localhost (127.0.0.1) | Резервный порт (D-E-N-T-E) при конфликте со сторонними СУБД |
| **5353** | UDP | mDNS / Bonjour Discovery | LAN Multicast | Разрешение доменного имени `http://dente-clinic.local:4000` |
| **4101** | UDP | LAN Node Discovery Beacon | LAN Broadcast | Автоматическое обнаружение сервера планшетами ассистентов |

## 4. Развертывание на macOS

Подробная документация пакета: [installer/macos/README.md](macos/README.md).

### Требования к системе
- Компьютер Apple Mac: Mac mini, MacBook Air/Pro, iMac.
- Процессор: Apple Silicon (M1, M2, M3, M4) или Intel x86_64.
- Операционная система: macOS 12 Monterey, macOS 13 Ventura, macOS 14 Sonoma, macOS 15 Sequoia.
- Установленный пакетный менеджер Homebrew (`/opt/homebrew` для Apple Silicon, `/usr/local` для Intel).
- Node.js LTS (версия >= 20) и PostgreSQL (версия 16–18).

### Шаг 1. Установка в 1 клик
Запустите командный файл установщика:
```bash
bash installer/macos/install-macos.sh
```
Скрипт выполнит:
1. Проверку системной архитектуры и наличия Homebrew.
2. Проверку версий Node.js и PostgreSQL (предложит автоустановку через `brew install`).
3. Инициализацию каталогов данных в `~/Library/Application Support/DenteCRM/`.
4. Запуск предстартового аудита `db-preflight.sh` (проверка `postmaster.pid` и выбор порта 5432/5438).
5. Инициализацию кластера `initdb` и создание учетной записи базы данных.
6. Регистрацию LaunchAgent `com.dente.crm.plist` и его активацию через `launchctl bootstrap`.
7. Создание ярлыка быстрого запуска `Dente CRM.command` на Рабочем столе.

### Шаг 2. Запуск интерфейса
- Двойной клик по ярлыку **`Dente CRM.command`** на Рабочем столе.
- Либо откройте веб-браузер по адресу: **`http://localhost:4000`**.
- Для планшетов в сети клиники: **`http://dente-clinic.local:4000`**.

### Шаг 3. Управление службой через терминал
Для оперативного контроля состояния используется утилита `manage-macos.sh`:
```bash
# Проверить статус службы, процессов и портов
./installer/macos/manage-macos.sh status

# Запустить сервер DENTE
./installer/macos/manage-macos.sh start

# Остановить сервер
./installer/macos/manage-macos.sh stop

# Перезапустить сервер
./installer/macos/manage-macos.sh restart

# Просмотр журналов в реальном времени
./installer/macos/manage-macos.sh logs

# Полная аппаратная и сетевая диагностика
./installer/macos/manage-macos.sh doctor
```

### Шаг 4. Безопасное удаление
При необходимости удаления программы запустите:
```bash
bash installer/macos/uninstall-macos.sh
```
В соответствии с Мандатом 8e (Doctor Autonomy), скрипт **автоматически сформирует резервную копию базы данных и всех документов** в архив `~/Desktop/DenteCRM_Backup_<timestamp>.tar.gz` перед остановкой и очисткой службы.

## 5. Развертывание на Windows

Подробная документация пакета: [installer/windows/README.md](windows/README.md).

### Требования к системе
- Компьютер: выделенный сервер, ПК администратора или рабочая станция врача.
- Операционная система: Windows 10 x64, Windows 11 x64, Windows Server 2019/2022.
- Права локального администратора Windows.
- PowerShell версии 5.1 или выше.

### Шаг 1. Настройка сетевого профиля и брандмауэра
Перед установкой или подключением планшетов запустите скрипт сетевой конфигурации с правами администратора:
```powershell
powershell -ExecutionPolicy Bypass -File installer\windows\Setup-DenteLanNetwork.ps1
```
Скрипт автоматически:
1. Определяет активный сетевой адаптер клиники (Ethernet или Wi-Fi).
2. Переключает сетевой профиль из режима `Public` (Общедоступная) в режим `Private` (Частная). В режиме Public брандмауэр Windows блокирует входящие соединения от планшетов.
3. Добавляет разрешающие правила в Windows Defender Firewall:
   - Входящий TCP 4000 (DENTE Web / API Gateway)
   - Входящий TCP 4100 (DENTE WebSocket Broker)
   - Входящий UDP 5353 (mDNS Discovery)
   - Входящий UDP 4101 (DENTE LAN Discovery Beacon)

### Шаг 2. Установка через инсталлятор `DenteSetup.exe`
1. Запустите инсталлятор `DenteSetup.exe` от имени администратора.
2. Инсталлятор Inno Setup:
   - Установит файлы приложения в `C:\Program Files\DenteCRM`.
   - Инициализирует постоянное хранилище в `C:\ProgramData\DenteCRM`.
   - Вызовет предстартовую проверку `db-preflight.ps1`.
   - Зарегистрирует системную службу `DenteService` под учетной записью `LocalSystem` (Session 0).
   - Настроит автоматический запуск индикатора системного трея при входе пользователя.
   - Запустит службу DENTE.

### Шаг 3. Индикатор системного трея (`DenteTray.ps1`)
После установки в области уведомлений Windows (системный трей рядом с часами) появляется индикатор состояния:
- Автоматический старт без всплывающего окна консоли через `DenteTray.vbs`.
- Фоновый опрос локального эндпоинта здоровья сервера каждые 30 секунд.
- Всплывающие уведомления Windows при сбоях питания или перезапуске службы.
- Контекстное меню по правому клику:
  - «Открыть DENTE в браузере» (`http://localhost:4000`)
  - «Перезапустить службу DENTE»
  - «Журналы сервера»
  - «Диагностика сети»

### Шаг 4. Управление службой через командную строку
Для быстрого администрирования в папке установки доступен командный файл `manage-service.cmd`:
```cmd
manage-service.cmd status    :: Проверить статус службы WinSW
manage-service.cmd start     :: Запустить службу
manage-service.cmd stop      :: Остановить службу
manage-service.cmd restart   :: Перезапустить службу
manage-service.cmd logs      :: Открыть папку с журналами
```

## 6. Механизм защиты от блэкаутов (Blackout Recovery)

Внезапное отключение электроэнергии в клинике (или аварийное выключение ПК) приводит к тому, что PostgreSQL оставляет файл блокировки `postmaster.pid`. При следующем запуске СУБД считает, что другой экземпляр уже работает, и аварийно завершает работу с ошибкой:
`FATAL: lock file "postmaster.pid" already exists`.

### Алгоритм работы Preflight-защиты:
1. Скрипт предстартовой проверки (`db-preflight.sh` на macOS / `db-preflight.ps1` на Windows / `auditPostmasterPid` в Node.js CLI) находит файл `postmaster.pid`.
2. Из первой строки считывается числовой идентификатор процесса (PID).
3. Проверяется статус процесса:
   - В macOS: системный вызов `ps -p <PID> -o comm=`.
   - В Windows: WMI-запрос `Get-Process -Id <PID>`.
4. Верификация имени исполняемого файла:
   - Если процесс жив и принадлежит `postgres`, подключение признается валидным.
   - Если процесс отсутствует в таблице процессов ОС, либо под данным PID запущен посторонний системный процесс (Recycled PID):
     * Lock-файл признается зависшим мусором после блэкаута.
     * Выполняется безопасное удаление (`unlinkSync`).
     * Запись в журнал аудита: `Purged stale postmaster.pid (PID was dead). Lock unblocked.`
5. Запуск PostgreSQL выполняется в штатном режиме без сбоев.

## 7. Разрешение конфликта портов с 1С (Port Collision Switch)

Если на сервере клиники уже установлена система 1С:Предприятие со встроенным сервером PostgreSQL:
1. Стандартный порт **5432** оказывается занят сторонней службой.
2. Модуль предварительной проверки выполняет TCP-проверку сокета `127.0.0.1:5432`.
3. При обнаружении занятости порта 5432 внешним процессом:
   - DENTE автоматически выбирает резервный порт **5438** (`D-E-N-T-E`).
   - Обновляет параметр `port = 5438` в конфигурации `postgresql.conf`.
   - Перезаписывает переменную `DATABASE_URL=postgres://dental:dental@127.0.0.1:5438/dental_crm` в файле конфигурации `dente.env`.
4. Конфликт устраняется полностью прозрачно для персонала клиники.

## 8. Проверка работоспособности после установки

После завершения установки на любой платформе выполните проверочный комплекс:

```bash
# 1. Запуск комплексной диагностики
npm run dente:doctor

# 2. Проверка генерации сетевой ссылки и QR-кода
npm run dente:info

# 3. Открытие интерфейса в браузере
# Нажмите на сгенерированную ссылку или перейдите по адресу:
http://localhost:4000
```

При успешной установке экран `dente:doctor` возвратит статус `[OK]` по всем 8 позициям проверки.

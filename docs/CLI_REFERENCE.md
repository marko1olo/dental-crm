# Справочное руководство по командной строке DENTE CLI

Настоящий документ содержит исчерпывающее техническое описание консольной утилиты `scripts/dente-cli.mjs`, поддерживаемых команд, форматов вывода, алгоритмов диагностики, кодов возврата и связанных сценариев автоматизации в `package.json`.

---

## 1. Архитектура и принципы реализации CLI

Утилита `scripts/dente-cli.mjs` разработана как универсальный кроссплатформенный инструмент администрирования DENTE Dental CRM:
- **Чистый Node.js (Zero External Dependencies)**: Утилита не использует сторонних бинарных утилит или npm-модулей в рантайме. Вся функциональность (включая генерацию матриц QR-кода ISO/IEC 18004) реализована на чистом JavaScript.
- **Кроссплатформенность**: Полная совместимость с macOS (Apple Silicon arm64 и Intel x64), Windows (x64) и Linux (x64 / arm64).
- **Прямой запуск и npm-алиасы**: Утилита может вызываться напрямую через Node.js либо через стандартные сценарии в `package.json`:
  - `npm run dente:doctor`
  - `npm run dente:preflight`
  - `npm run dente:info`

### Синтаксис вызова
```bash
# Прямой вызов через node
node scripts/dente-cli.mjs <command>

# Вызов через npm scripts
npm run dente:<command>
```

## 2. Команда `dente doctor` (Диагностика окружения)

Команда `doctor` предназначена для глубокой инструментальной проверки аппаратного окружения, сетевых портов, файловой системы и СУБД перед запуском системы либо при расследовании инцидентов.

### Способы вызова
```bash
node scripts/dente-cli.mjs doctor
npm run dente:doctor
```

### Диагностируемые компоненты и критерии проверки:
1. **OS Platform (Операционная система и архитектура)**:
   - Проверяет платформу (`darwin`, `win32`, `linux`) и процессорную архитектуру (`x64`, `arm64`).
   - Статус `OK`: поддерживаемая платформа и архитектура (например, `macOS 14.5 (arm64)` или `Windows 10.0.26200 (x64)`).
   - Статус `FAIL`: неподдерживаемая платформа.
2. **Node.js Engine (Версия рантайма)**:
   - Анализирует текущую версию Node.js (`process.version`).
   - Статус `OK`: мажорная версия $\ge 20$ (LTS Iron / Jod).
   - Статус `FAIL`: версия $< 20$ (рантайм не поддерживает современные API Fastify v5 и встроенные криптографические примитивы).
3. **Port 4000 (DENTE Web / API Gateway)**:
   - Проверяет сетевой сокет `127.0.0.1:4000`.
   - Сообщает: `Active (Service Running)` при запущенном сервере либо `Available (Ready to bind)` при готовности порта к запуску.
4. **Port 4100 (DENTE WebSocket Event Broker)**:
   - Проверяет сетевой сокет `127.0.0.1:4100`.
   - Сообщает: `Active (Service Running)` либо `Available (Ready to bind)`.
5. **PostgreSQL Ports (Сетевые порты СУБД)**:
   - Одновременно опрашивает сокеты `127.0.0.1:5432` (основной порт) и `127.0.0.1:5438` (резервный порт).
   - Статус `OK`: запущен хотя бы один из портов СУБД.
   - Статус `WARN`: оба порта не отвечают (PostgreSQL остановлен или требует запуска).
6. **LAN Network IP (Сетевой адрес в клинике)**:
   - Автоматически сканирует сетевые адаптеры компьютера с интеллектуальной фильтрацией виртуальных интерфейсов.
   - Статус `OK`: найден рабочий адрес в частной клинической подсети (например, `192.168.1.103`).
   - Статус `WARN`: доступен только локальный петлевой адрес `127.0.0.1` (отсутствует подключение к локальной сети клиники).
7. **Disk Space (Свободное дисковое пространство)**:
   - Вызывает системный вызов `statfs` для корневого раздела или рабочей директории.
   - Статус `OK`: свободно $\ge 2.0\text{ ГБ}$ дискового пространства для надежного хранения рентгеновских снимков и журнала WAL PostgreSQL.
   - Статус `FAIL`: свободно $< 2.0\text{ ГБ}$ (риск аварийной остановки базы данных).
8. **Database Connection (Подключение к PostgreSQL)**:
   - Выполняет попытку прямого подключения к базе данных через библиотеку `pg` с таймаутом 2500 мс и выполнением проверочного запроса `SELECT current_database(), version()`.
   - При отсутствии установленной клиентской библиотеки переходит на TCP-рукопожатие сокета.
   - Статус `OK`: успешная аутентификация и чтение версии СУБД.
   - Статус `FAIL`: ошибка аутентификации, неверный пароль либо недоступность базы.

### Коды возврата (Exit Codes)
- **`0`**: Все проверки завершились успешно со статусом `OK` (допускаются предупреждения со статусом `WARN`).
- **`1`**: Зафиксирован как минимум один критический сбой (`FAIL`).

## 3. Команда `dente preflight` (Предстартовый арбитраж)

Команда `preflight` вызывается диспетчерами служб (`service-runner.sh`, `service-runner.cmd`, `service-bootstrap.mjs`) перед инициализацией кластера PostgreSQL и запуском Node.js.

### Способы вызова
```bash
node scripts/dente-cli.mjs preflight
npm run dente:preflight
```

### Выполняемые процедуры:

### 1. Blackout Crash Recovery (Аудит lock-файла `postmaster.pid`)
Функция `auditPostmasterPid` сканирует каталоги данных PostgreSQL (`.data/pg18`, `apps/api/dente_local_db`, `PGDATA`, `C:\ProgramData\DenteCRM\data\pg18`):
- Если файл `postmaster.pid` отсутствует: фиксируется статус `OK` (корректное выключение СУБД).
- Если файл `postmaster.pid` обнаружен:
  * Из первой строки файла парсится числовой PID процесса;
  * Проверяется активность процесса через системный вызов `process.kill(pid, 0)`:
    - Если процесс активен (`isAlive = true`): фиксируется рабочий статус СУБД `Active PostgreSQL instance detected`.
    - Если процесс отсутствует в ОС либо ошибка `ESRCH`: процесс погиб при отключении питания. Файл `postmaster.pid` признается зависшим мусором и удаляется с диска через `fs.unlinkSync(pidFile)`.
    - Защита от Recycled PID: скрипты платформы дополнительно проверяют принадлежность PID исполняемому файлу `postgres.exe` / `postgres`.

### 2. Database Port Arbitration (Автоматический выбор порта СУБД)
Функция `selectDatabasePort` предотвращает конфликт с установленными СУБД сторонних программ (например, 1С:Предприятие):
- Выполняет параллельный асинхронный опрос портов 5432 и 5438.
- Если порт 5432 свободен или уже слушается активным PostgreSQL DENTE: выбирается основной порт **5432**.
- Если порт 5432 занят сторонним приложением, а порт 5438 свободен или слушается: DENTE автоматически переключается на резервный порт **5438** (`D-E-N-T-E`).
- Обновляет переменные окружения для Fastify API.

### 3. Schema Migrations Audit (Проверка целостности миграций Drizzle ORM)
Функция `checkMigrations` инспектирует каталоги миграций (`apps/api/drizzle/` и `drizzle/`):
- Подсчитывает общее количество `.sql` файлов миграций на диске.
- Проверяет целостность файла журнала `meta/_journal.json` и соответствие количества записей в журнале реальным SQL-файлам.
- Определяет наименование последней актуальной миграции.

### Коды возврата (Exit Codes)
- **`0`**: Все проверки пройдены, кластер готов к старту.
- **`1`**: Обнаружена критическая ошибка (например, невозможность удалить заблокированный lock-файл из-за прав доступа).

### Пример вывода команды:
```text
========================================================================
  DENTE Dental CRM — Preflight & Cluster Arbitration Engine
========================================================================
  [OK]    Crash Recovery (PID)    : Clean shutdown state verified (no postmaster.pid lock found)
  [OK]    DB Port Arbitration     : Port 5432 active and responding (PostgreSQL Default)
  [OK]    Schema Migrations       : 179 migrations verified on disk (latest: 0201_sanpin_sterilizer_equipments.sql)
------------------------------------------------------------------------
  [OK] Preflight checks passed. DENTE CRM cluster is ready to boot.
========================================================================
```

## 4. Команда `dente info` (Сетевой доступ и терминальный QR-код)

Команда `info` служит для моментальной интеграции планшетов врачей и ассистентов в локальную сеть клиники без необходимости ручного поиска IP-адресов.

### Способы вызова
```bash
node scripts/dente-cli.mjs info
npm run dente:info
```

### Алгоритм работы команды:
1. **Интеллектуальный поиск локального IP (Функция `detectLanIp`)**:
   - Сканирует все сетевые интерфейсы через `os.networkInterfaces()`.
   - Исключает петлевые адреса (`internal: true`) и интерфейсы IPv6.
   - Фильтрует виртуальные адаптеры, туннели и служебные мосты: `vethernet`, `docker`, `wsl`, `tailscale`, `radmin`, `vpn`, `tap`, `tun`, `br-*`.
   - Приоритизирует частные адреса локальной сети:
     1. Подсети класса C (`192.168.x.x`, наивысший приоритет);
     2. Подсети класса A (`10.x.x.x`);
     3. Подсети класса B (`172.16.x.x`–`172.31.x.x`).
2. **Генерация матрицы QR-кода (Стандарт ISO/IEC 18004)**:
   - Реализована на чистом JavaScript внутри `scripts/dente-cli.mjs` без внешних зависимостей.
   - Автоматически выбирает минимальную версию QR-кода (версии 1–10) в зависимости от длины URL.
   - Использует кодирование с коррекцией ошибок уровня **M** (до 15% повреждений) по алгоритму Рида-Соломона (GF($2^8$)).
   - Применяет маску шаблона Mask 0.
3. **Псевдографический терминальный рендерер (Функция `renderQrTerminalString`)**:
   - Для отрисовки квадратных модулей в текстовом терминале использует символы половинных блоков Юникода (Unicode Half-Block Elements):
     * `\u2580` (`▀` — верхняя половина заполнена);
     * `\u2584` (`▄` — нижняя половина заполнена);
     * `\u2588` (`█` — полный блок);
     * пробел (` ` — пустой блок).
   - Группирует две строки матрицы QR-кода в одну строку текстового терминала, обеспечивая идеальное квадратное соотношение сторон и мгновенное считывание камерой смартфона или планшета.

## 5. Дополнительные проверочные скрипты в `package.json`

Помимо утилиты `dente-cli.mjs`, в проекте действуют системные скрипты контроля качества и целостности:

| Скрипт | Команда | Назначение |
| :--- | :--- | :--- |
| **`check:encoding`** | `npm run check:encoding` | Сканирует все файлы монорепозитория на строгое соответствие UTF-8 без BOM и отсутствие символов Mojibake. |
| **`check:css-tokens`** | `npm run check:css-tokens` | Контролирует отсутствие хардкода цветов (`#fff`, `#000`) в обход дизайн-токенов (`var(--paper)`). |
| **`check:tracked-ignored`** | `npm run check:tracked-ignored` | Проверяет репозиторий на случайное отслеживание игнорируемых файлов (.env, артефакты сборки). |
| **`check:dynamic-imports`** | `npm run check:dynamic-imports` | Контролирует корректность путей ленивых импортов компонентов. |
| **`verify:cross-platform`** | `npm run verify:cross-platform` | Комплексный запуск кроссплатформенных тестов (Windows/macOS/Linux). |
| **`smoke:chains`** | `npm run smoke:chains` | Запуск цепочек сквозного тестирования сценариев врачебного приёма и кассы. |

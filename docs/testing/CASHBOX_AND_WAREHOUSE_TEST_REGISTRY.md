## 3. ДЕТАЛЬНОЕ ОПИСАНИЕ ПРОВЕРЯЕМЫХ ИНВАРИАНТОВ

### Тест 1. Мульти-тендерный сплит-чекаут (Карта + Наличные + Семейный депозит)
* **Сценарий**: Оплата приёма на сумму 10 000.00 ₽ (1 000 000 копеек):
  * Безналичные / Карта (Тег 1081): 5 000.00 ₽ (500 000 коп.)
  * Наличные (Тег 1031): 3 000.00 ₽ (300 000 коп.)
  * Семейный депозит / аванс (Тег 1215): 2 000.00 ₽ (200 000 коп.)
* **Математическая целостность**:
  $$500\,000 + 300\,000 + 200\,000 \equiv 1\,000\,000 \text{ коп.}$$
  Нулевая копеечная погрешность без плавающей точки (`float`).
* **Аудит транзакции в БД**:
  * Таблица `payments`: формируются 3 отдельные проводки с методами `card`, `cash` и `family_wallet`.
  * Таблица `family_groups`: остаток семейного кошелька уменьшается ровно на 2 000.00 ₽ (с 5 000.00 ₽ до 3 000.00 ₽).
  * Таблица `fiscal_receipt_queue`: регистрируется чек с тегами ФФД 1.2: `electronicKopecks = 500000`, `cashKopecks = 300000`, `advanceOffsetKopecks = 200000`.
  * Статус визита переводится в `signed`, позиция лечения — в `completed`.

### Тест 2. Soft Negative Stock и фоновое списание по техкартам (Мандат 8aa)
* **Сценарий**: Списание композитного материала со склада при начальном физическом остатке `stockQuantity = 0.000` (накладная от поставщика задерживается).
* **Поведение**:
  * Запрос завершается со статусом `200 OK` (ноль 400/409 ошибок, врач у кресла НЕ блокируется).
  * Ответ содержит `isOverdraft: true` и информационное предупреждение для склада.
  * В БД остаток материала переходит в отрицательное сальдо (минус 1.000).
  * Создается складская проводка с флагом `isOverdraft: true`, сохраняя строгий финансовый след.

### Тест 3. Касса 54-ФЗ без барьеров: Отсутствие ИНН у физических лиц (Мандат 8n)
* **Сценарий**: Проведение чека физического лица через `POST /api/fiscal/receipts` без реквизита `customerInn`.
* **Законодательное обоснование**: Ст. 4.7 Федерального закона № 54-ФЗ (Тег 1228 применяется исключительно для расчетов между организациями и ИП).
* **Поведение**: Чек формируется со статусом `201 Created`, присваивается номер фискального документа.
* **Контр-проверка**: Попытка сформировать чек для юрлица (`payerType = legal_entity`) без ИНН строго возвращает `400 ValidationError`.

### Тест 4. 100% Гарантийная скидка врача (Мандат 8e)
* **Сценарий**: Гарантийная переделка реставрации или бесплатный приём со скидкой 100% (`totalKopecks = 0`).
* **Поведение**:
  * Чеки с нулевой суммой категорически НЕ отправляются в сетевой сокет ККТ (защита от аппаратной ошибки драйвера).
  * Сервер формирует внутренний уставный акт списания/гарантии `АКТ-ГАР-ГГГГ-ХХХХ` со статусом `isWarrantyZeroAct: true`, `fiscalDocumentNumber = "0"`.

### Тест 5. ACID Идемпотентность и защита от повторных списаний (Мандат 8zp)
* **Сценарий**: Повторная отправка запроса сплит-оплаты с тем же заголовком `Idempotency-Key` / `clientMutationId`.
* **Поведение**:
  * Сервер возвращает статус `200 OK` с сохраненным телом транзакции.
  * Баланс семейного кошелька НЕ списывается повторно (остается строго 3 000.00 ₽).
  * Количество записей в таблице `payments` не удваивается.

### Тест 6. Фаззинг копеек без потерь (Hamilton-Hare Float Defense)
* **Сценарий**: 100 псевдослучайных сумм с нечетными копейками (1 333.33 ₽, 7 777.77 ₽, 9 999.99 ₽, 1 000.01 ₽).
* **Поведение**: Распределение на 3 неравные доли (50%, 30%, 20%) гарантирует строгую целочисленную сумму:
  $$\sum \text{Tenders} \equiv \text{TotalBillKopecks}$$
  Потеря копеек строго равна 0.

# Спецификация и дорожная карта внедрения премиального модуля STOM-PLAN

## 1. Сравнительный анализ: Текущая реализация vs Целевая архитектура (STOM-PLAN Premium)

В ходе аудита текущей кодовой базы DENTE CRM (`apps/web/src/components/odontogram/ToothChart.tsx`, `TreatmentEstimator.tsx`, `planPricing.ts`) и целевого концепта (mamai.txt) выявлены следующие архитектурные разрывы:

### 1.1 Интерактивная зубная формула (ToothChart.tsx)
- **Текущее состояние**: 
  - Реализована векторная SVG-формула.
  - Поддерживается "Ловушка 5 поверхностей" (MOD Trap): поверхности O, V, L/P, D, M интерактивны и независимы.
  - Отрисовываются градиенты, кариес, пульпит, имплантаты.
  - **Отсутствует**: Динамическая анимация костной атрофии (0-100%) для отсутствующих зубов.
  - **Отсутствует**: Управление сверхкомплектными зубами (гипердонтия) вне стандарта ISO 3950.
  - **Отсутствует**: Интеграция спектральной шкалы оттенков Vita (A1–D4, Bleach).

### 1.2 Клиническая логика и биомеханика
- **Текущее состояние**:
  - Строгий подбор услуг по прайсу (`planPricing.ts`), запрет на хардкод цен.
  - **Отсутствует**: Алгоритмический учет феномена Попова-Годона (риск выдвижения антагониста при отсутствии зуба).
  - **Отсутствует**: Учет биотипа десны (автоматическое предложение пластики мягких тканей при тонком биотипе перед имплантацией).
  - **Отсутствует**: Автоматическая инъекция обязательных процедур (например, стерильного набора и анестезии при хирургии).

### 1.3 Коммерческие предложения и AI (Groq / Llama 3 70B)
- **Текущее состояние**:
  - Формируется единый линейный план лечения без альтернатив.
  - ИИ-объяснения на основе психотипа пациента отсутствуют.
  - Voice AI (Whisper) используется только для диктовки диагноза.
- **Целевое состояние**:
  - Трехвариантное коммерческое предложение: «Эконом», «Оптимальный», «VIP».
  - Гибридная AI-архитектура: расчеты строго детерминированы (Node.js/Fastify), а Llama 3 70B (через Groq API) генерирует текстовое обоснование с адаптацией под психотип пациента (Тревожный, Рациональный, Эстетический).

## 2. Архитектурная спецификация модуля STOM-PLAN

### 2.1 Модуль визуализации (Frontend SVG)
В файл `ToothChart.tsx` необходимо внедрить:
1. **Слайдер атрофии**: Пропс `boneAtrophyLevel?: number` (0-100). При значении > 0 отрисовывается SVG-контур резорбированного альвеолярного гребня с изменением радиуса `rx`/`ry`.
2. **Палитра Vita**: Добавление цветовых фильтров для коронок и виниров.
3. **Изоляция рендеринга**: Использование `React.memo` на уровне каждого зуба во избежание перерисовки всей челюсти при изменении цвета одного винира.

### 2.2 Биомеханический движок (Rules Engine)
Создание сервиса `apps/api/src/services/biomechanics.ts` и `apps/web/src/lib/biomechanics.ts`:
- **Правило 1 (Попов-Годон)**: При статусе `Missing` зуба N, проверка статуса зуба-антагониста. Если он `Healthy` или `Filled`, выдача `WARNING: Риск зубоальвеолярного удлинения антагониста`.
- **Правило 2 (Тонкий биотип)**: При `gum_biotype === 'thin'` и операции `Implant`, добавление обязательной услуги "Пластика мягких тканей" (ССТ/СДТ).
- **Правило 3 (Защита гарантии)**: При разрушении коронки > 50% и выборе композитной реставрации, добавление флага: "Ограничение гарантийного срока до 6 месяцев в связи с риском фрактуры".

### 2.3 Гибридная AI-генерация планов (Groq Llama 3)
1. **Детерминированный слой**: Алгоритм собирает 3 пакета услуг (Эконом: мосты/съемные, Оптима: импланты стандарт, VIP: импланты премиум + цирконий). Все цены строго из `planPricing.ts`.
2. **Слой генерации (Prompting)**:
   Отправка JSON-схемы в Groq API (модель Llama 3 70B, лимиты 30 RPM бесплатного тира покрывают нужды клиники):
   ```json
   {
     "patient_psychotype": "anxious",
     "clinical_data": { ... },
     "plans": { "vip": [...], "optima": [...], "economy": [...] }
   }
   ```
3. **Кэширование**: Для стандартных планов (например, только профессиональная гигиена) ИИ не вызывается, используется заранее закэшированный шаблон для снижения расхода токенов.

## 3. Дорожная карта внедрения (Roadmap)

### Этап 1: Доработка интерактивной формулы (Недели 1-2)
- [ ] Интеграция SVG-контуров для отображения степени костной атрофии (0-100%).
- [ ] Добавление поддержки сверхкомплектных зубов (интерфейс добавления элемента 9 или дистопированного зуба).
- [ ] Интеграция спектральной шкалы Vita в состояние зуба.

### Этап 2: Биомеханические алгоритмы и валидаторы (Недели 2-3)
- [ ] Реализация детектора феномена Попова-Годона.
- [ ] Реализация зависимости "Тонкий биотип десны + Имплантация = Обязательная пластика".
- [ ] Добавление юридических оговорок в `TreatmentEstimator.tsx` при >50% разрушении.

### Этап 3: Трехвариантное планирование (Недели 3-4)
- [ ] Модификация `resolvePlanSuggestions` в `planPricing.ts` для поддержки генерации массивов услуг под категории Эконом/Оптима/VIP.
- [ ] Обновление UI `TreatmentEstimator.tsx` для отображения табов (VIP, Оптимальный, Эконом).

### Этап 4: Интеграция AI-сопровождения через Groq (Недели 4-5)
- [ ] Разработка Fastify API-роута `/api/ai/treatment-explanation` с подключением Groq API (Llama 3 70B).
- [ ] Внедрение системных промптов (System Prompts) для 3 психотипов (Тревожный, Рациональный, Эстетический).
- [ ] Внедрение системы кэширования для стандартных протоколов лечения.

### Этап 5: Тестирование и Комплаенс (Неделя 6)
- [ ] Проверка отсутствия галлюцинаций LLM в финансовых расчетах (strict separation of concerns).
- [ ] Интеграция сгенерированного PDF с модулем подписания УКЭП (КриптоПро CSP 5.0) для передачи в ЕГИСЗ (соответствие 323-ФЗ).

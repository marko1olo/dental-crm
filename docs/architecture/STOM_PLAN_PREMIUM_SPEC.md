## 1. Сравнительный анализ: Текущая реализация vs Целевая архитектура (STOM-PLAN)

В кодовой базе DENTE CRM реализован полнофункциональный промышленный модуль 3-уровневого параллельного планирования лечения (`packages/shared/src/treatment-plans/treatmentPlanEngine.ts`, `apps/web/src/components/treatment-plans/`):

### 1.1 Интерактивная зубная формула (ToothChart.tsx)
- **Текущее состояние**:
  - Реализована векторная SVG-формула (FDI 11–48 постоянного прикуса и 51–85 молочного).
  - Поддерживается "Ловушка 5 поверхностей" (MOD Trap): поверхности O, V, L/P, D, M интерактивны и независимы.
  - Отрисовываются кариес, пульпит, периодонтит, коронки, пломбы, дентальные имплантаты.
  - **Перспектива развития**: Динамическая анимация костной атрофии (0-100%) для зон длительной адентии.
  - **Перспектива развития**: Спектральная шкала оттенков Vita (A1–D4, Bleach) в карточке зуба.

### 1.2 Клиническая логика и биомеханика
- **Текущее состояние**:
  - Строгий подбор услуг по номенклатуре 804н и прайсу клиники, запрет на хардкод цен.
  - Клинический движок правил (`packages/shared/src/clinical-rules/`, `apps/api/src/routes/clinical.ts`): предупреждения о несовместимости, обязательные сопутствующие услуги (анестезия, оптрагейт, стерильный пакет).
  - **Мандат 8e**: Правила носят рекомендательный характер — врач обладает 100% автономией и может применить скидку вплоть до 100% на гарантийные переделки.
  - **Перспектива развития**: Автоматическое предупреждение о риске выдвижения антагониста по Попову-Годону при длительном отсутствии зуба.

### 1.3 Коммерческие предложения и 3-уровневое планирование (Production Реализовано)
- **Текущее состояние (РЕАЛИЗОВАНО В PRODUCTION)**:
  - Реализован трехвариантный параллельный расчет: **«Эконом»**, **«Оптимум»** (рекомендованный, `isRecommended: true`), **«Премиум»** (`packages/shared/src/treatment-plans/treatmentPlanEngine.ts`).
  - Все расчеты строго детерминированы, ведутся в целочисленных копейках (`BIGINT`, `isPennyExact: true`) с гарантией отсутствия погрешностей `float`.
  - Каждый тариф автоматически раскладывается на 3 клинических этапа (1. Санация/Терапия -> 2. Хирургия/Имплантация -> 3. Ортопедия/Эстетика).
  - Разделение стоимости на оплату работы врача и себестоимость материалов (`splitLaborAndMaterials`).
  - Расчет рассрочки (3, 6, 12, 24 мес.) и расчет суммы социального налогового вычета 13% НДФЛ (ФНС КНД 1151156).
  - Для мобильных устройств ($\le 640\text{px}$) реализован нативный Segmented Control `[ Эконом | ★ Оптимум | Премиум ]`, исключающий 2500px вертикальный скролл (Мандат THE HAMMER §VI.3).
  - Готовые UI-модули: `TreatmentPlan3TierComparison.tsx`, `TreatmentPlanPresenterModal.tsx`, `TreatmentPlanPhased4StageView.tsx`, `TreatmentPlanCompletedActPrint.tsx`.

## 2. Архитектурная спецификация модуля STOM-PLAN

### 2.1 Модуль визуализации (Frontend SVG)
В файл `ToothChart.tsx` необходимо внедрить:
1. **Слайдер атрофии**: Пропс `boneAtrophyLevel?: number` (0-100). При значении > 0 отрисовывается SVG-контур резорбированного альвеолярного гребня с изменением радиуса `rx`/`ry`.
2. **Палитра Vita**: Добавление цветовых фильтров для коронок и виниров.
3. **Изоляция рендеринга**: Использование `React.memo` на уровне каждого зуба во избежание перерисовки всей челюсти при изменении цвета одного винира.

### 2.2 Биомеханический движок (Rules Engine)
Создание сервиса `apps/api/src/services/biomechanics.ts` и `apps/web/src/lib/biomechanics.ts`:
- **Правило 1 (Попов-Годон)**: При статусе `Missing` зуба N, проверка статуса зуба-антагониста. Если он `Healthy` или `Filled`, выдача `WARNING: Риск зубоальвеолярного удлинения антагониста`.
- **Правило 2 (Тонкий биотип)**: При `gum_biotype === 'thin'` и операции `Implant`, добавление обязательной услуги "Пластика мягких тканей" (ССТ/СДТ).
- **Правило 3 (Защита гарантии)**: При разрушении коронки > 50% и выборе композитной реставрации, добавление флага: "Ограничение гарантийного срока до 6 месяцев в связи с риском фрактуры".

### 2.3 Гибридная AI-генерация планов (Groq Llama 3)
1. **Детерминированный слой**: Алгоритм собирает 3 пакета услуг (Эконом: мосты/съемные, Оптима: импланты стандарт, VIP: импланты премиум + цирконий). Все цены строго из `planPricing.ts`.
2. **Слой генерации (Prompting)**:
   Отправка JSON-схемы в Groq API (модель Llama 3 70B, лимиты 30 RPM бесплатного тира покрывают нужды клиники):
   ```json
   {
     "patient_psychotype": "anxious",
     "clinical_data": { ... },
     "plans": { "vip": [...], "optima": [...], "economy": [...] }
   }
   ```
3. **Кэширование**: Для стандартных планов (например, только профессиональная гигиена) ИИ не вызывается, используется заранее закэшированный шаблон для снижения расхода токенов.

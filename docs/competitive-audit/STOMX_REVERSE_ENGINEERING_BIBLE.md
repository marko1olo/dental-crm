## 2. АНАТОМИЯ ЗУБНОЙ ФОРМУЛЫ И СПРАВОЧНИК ДЕФЕКТОВ ЗУБОВ (89 ПОЗИЦИЙ)

### 2.1. Структура зубного ряда (`teeth.json` / `catalogs/teeth_adult.json`, `teeth_child.json`)
В отличие от упрощенных представлений, где зуб описывается только номером от 11 до 48, в StomX зубная система представлена 3 сущностями:
1. **Постоянные зубы (Adult):** `quoter: 1..4`, номера 18..48 (`is_child: 0`, `type: "T"`).
2. **Молочные зубы (Pediatric):** `quoter: 1..4`, номера 51..85 (`is_child: 1`, `type: "T"`).
3. **Челюсти и дуги (Jaw entities):** верхняя челюсть (`JU`, `id: 54`, `type: "J"`), нижняя челюсть (`JL`, `id: 55`, `type: "J"`), центральная окклюзия (`C`, `id: 53`, `type: "J"`). Позволяют привязывать диагнозы и конструкции ко всей челюсти сразу (полные съемные протезы, синус-лифтинг, пародонтит, шинирование).

## 5. АРХИТЕКТУРА НАЦИОННОГО СЛОЯ ELECTRON И ПОЛНЫЙ РАЗБОР `ipc_handlers_full.js`

В Новом Завозе десктопный слой Electron раскрыт в файле `ipc_handlers_full.js` (469 строк кода). Модуль регистрирует 8 функциональных групп обработчиков IPC:
1. `registerFileHandlers()` — Локальные файлы и томография (КТ)
2. `registerCryptoHandlers()` — Криптографические операции КриптоПро CSP
3. `registerConfigHandlers()` — Системные настройки и перезапуск GPU
4. `registerPDFHandlers()` — Создание и печать PDF без сбоев GPU
5. `registerDownloadModeHandlers()` — Управление скачиванием PDF (`inline` vs `attachment`)
6. `registerCadesHandlers()` — Виртуальный COM-мост CAdESCOM
7. `registerQesWindowHandlers(getMainWindow)` — Окно УКЭП и отправка в ЕГИСЗ
8. `registerFrontendUpdateHandlers()` — Фоновое OTA-обновление Angular

### 5.1. Прямой CLI-вызов КриптоПро CSP без браузерного плагина:
StomX полностью отказался от ненадежного расширения браузера `cadesplugin` в пользу прямого вызова консольных утилит через Node.js `child_process.exec`:

```javascript
// Чтение персонального хранилища сертификатов:
certmgr.exe -list -store uMy > certificates.txt

// Формирование отсоединенной электронной подписи PKCS#7 (CAdES-BES):
cryptcp.x64.exe -sign -detached -nochain -thumbprint <THUMBPRINT> -dir "<TEMP_DIR>" "<TEMP_FILE>"
```

**Ключевые инженерные решения StomX в IPC:**
- **Защита от параллельных гонок (`#4975`):** В ранних версиях файл подписи назывался статично `sign.xml` / `sign.xml.sgn`. При параллельном или отмененном подписании происходило взаимное затирание данных. В `ipc_handlers_full.js` внедрен уникальный тег:
  ```javascript
  const requestId = input.requestId;
  const fileTag = requestId != null ? '-' + String(requestId).replace(/[^a-z0-9]/gi, '') : '';
  const tmpFile = tmpDir + sep + 'sign' + fileTag + '.xml';
  const sgnFile = tmpFile + '.sgn';
  ```
- **Декодирование CP1251:** Утилиты КриптоПро в Windows отдают консольный вывод в кодировке `cp1251`. Модуль использует `iconv.decode(data, 'cp1251')` для парсинга кириллических имен владельцев и издателей сертификатов.
- **Очистка временных файлов (`cleanup`):** После считывания сформированной подписи `.sgn` файлы `.xml` и `.sgn` гарантированно удаляются через `fs.unlink`.

### 5.2. Изоляция PDF-рендерера и борьба со сбоями GPU:
На слабых компьютерах клиник (встроенные видеокарты Intel/AMD) встроенный Chromium PDF Viewer часто приводит к падению графического контекста (`GPU process crash`). StomX решает это изоляцией параметров:
```javascript
const testOptions = {
  width: 800,
  height: 600,
  webPreferences: {
    additionalArguments: gpuDisabled
      ? ['--disable-gpu', '--disable-gpu-compositing', '--disable-software-rasterizer']
      : [],
  },
};
```
Параметры `disable_gpu_pdf` и `disable_gpu_all` сохраняются в конфигурационном файле (`config-manager.js`) и управляются через IPC без переустановки приложения.

### 5.3. Запуск томограмм (КТ) и файлов ОС:
Обработчик `outpatient-kt-open` проверяет физическое наличие файла перед вызовом ОС:
```javascript
if (fs.existsSync(pt)) {
  shell.openPath(path.normalize(pt)).then();
} else {
  new Notification({ title: 'Ошибка', body: 'Файл не найден' }).show();
}
```
Поддерживаются 3 типа: `outpatient_kt_file` (запуск программы просмотра КТ), `outpatient_kt_dir` (открытие папки со срезами DICOM) и `outpatient_kt_url` (`shell.openExternal`).

### 5.4. Фоновое OTA-обновление Angular-клиента:
Обработчик `frontend-update:download` асинхронно скачивает ZIP-архив новой версии Angular бандла в фоновом потоке, распаковывает в директорию приложения через `adm-zip` и возвращает результат в Angular через Promise, не блокируя работу врача.

## 9. МОДЕЛИ НАЧИСЛЕНИЯ ЗАРАБОТНОЙ ПЛАТЫ

В StomX реализован гибкий расчет ЗП (`/api/salary`):
- **Сдельная процентная ставка врача:**
  $$\text{Начисление} = (\text{Сумма услуги} - \text{Лаборатория} - \text{Материалы}) \times \%_{\text{врача}} + \text{Фикс}_{\text{услуги}}$$
- **Индивидуальные ставки на услуги (`salary_price`):** Возможность установить фиксированную оплату врачу за конкретную процедуру независимо от скидки пациенту.
- **Премии и штрафы (`payment-rewards`):** Корректировка итогового расчетного листка перед формированием ведомости.

## 15. ПОШАГОВЫЙ ПЛАН ИСПОЛЬЗОВАНИЯ НАРАБОТОК STOMX В CLINIC MVP

1. **Фаза 1: Клинический базис (Одонтограмма, МКБ-10 и шаблоны 043/у)**
   - Импортировать тексты 448 медицинских протоколов из `outpatient_templates_FULL/` в таблицу `outpatient_templates` PostgreSQL Clinic MVP.
   - Обеспечить врачу доступ к ним через существующий 1-клик селектор шаблонов в `DentalMedicalCard043uForm.tsx` с сохранением автономии врача (Мандат 8e).
2. **Фаза 2: Юридический контур и библиотека ИДС**
   - Перенести формулировки рисков из 23 шаблонов ИДС StomX в реестр согласий DENTE (`InformedConsentModal.tsx`).
   - Синхронизировать переменные подстановки с `template_variables.json` для автоматического заполнения реквизитов клиники, врача и пациента.
3. **Фаза 3: Десктопный агент УКЭП (КриптоПро CSP)**
   - Для десктопной сборки DENTE перенести архитектуру прямого вызова `cryptcp.x64.exe` и `certmgr.exe` из `ipc_handlers_full.js`, полностью исключив зависимость от сбоящих браузерных плагинов.
4. **Фаза 4: Ортодонтия и элайнеры**
   - Закрепить связку ортодонтического плана лечения (`orthodonticMedplans`) с журналом наблюдения активации дуг и смены капп элайнеров.

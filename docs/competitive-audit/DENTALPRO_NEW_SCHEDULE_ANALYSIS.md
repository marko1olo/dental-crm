## 1. ИСПОЛНИТЕЛЬНОЕ РЕЗЮМЕ (EXECUTIVE SUMMARY)

Компания DentalPRO осуществляет фундаментальный переход с устаревшего поколения своей платформы (**expo25pro4**) на кардинально переработанное ядро (**expo26**). Главной точкой трансформации является модуль **Расписания (Scheduler)** — ключевой рабочий экран врачей, администраторов и кураторов клиники.

В старой версии (expo25) расписание представляло собой тяжелый монолит на базе **jQuery 3.5.1 + Bootstrap 4 + jQuery UI + Moment.js**, где каждая ячейка и карточка позиционировались через абсолютные inline-пиксели (`top: 320px; height: 120px; left: 280px`). При масштабировании на 15+ врачей и 50+ визитов система страдала от лагов при рендеринге (задержка 2–4 секунды), визуальных окклюзий (гигантские синие стрелки пагинации перекрывали текст записей) и громоздких модальных окон на весь экран.

В новой версии (expo26) DentalPRO переписали расписание с нуля:
1. **Frontend-ядро:** Переход на **React 18 / 19 Fiber** с роутингом **React Router 6 (Data Router API)**.
2. **Математика сетки:** Отказ от inline-пикселей в пользу чистых **CSS Custom Properties (`--slot-position`, `--slot-size`, `--card-bg-color`)**, что исключило reflow/repaint при ресайзе.
3. **Эргономика создания записи:** Отказ от блокирующих полноэкранных модалок в пользу **интерактивной левой шторки (Drawer)**, сохраняющей визуальный контекст сетки при бронировании.
4. **Умный автоподбор («Найти варианты»):** Алгоритмический поиск свободных окон по врачу, креслу и филиалу без необходимости ручного пролистывания дней.
5. **Контекстный микро-HUD:** 1-кликовое открытие панели с **6 базовыми клиническими действиями** (ЭМК 043/у, повторная запись, анкета, план лечения, протокол визита, лист ожидания).
6. **Векторная система бейджей:** 17 специализированных клинических и финансовых иконок (`schi-1` .. `schi-17`), позволяющих за 1 секунду оценить статус пациента (аллергия, первичка, договор, долг, рассрочка, ЗТЛ, звонок колл-центра).

## 3. МАТЕМАТИКА ТАЙМ-СЕТКИ И CSS-АРХИТЕКТУРА

В отличие от устаревших подходов с вычислением абсолютных пикселей в цикле JavaScript, в expo26 вся геометрия делегирована нативному CSS-движку браузера:

### 3.1. Формула расчетных переменных
Каждая карточка визита (`.scheduler-card`) и блок служебного времени (`.block-element`) рендерится со следующими CSS-переменными в атрибуте `style`:
```html
<div class="scheduler-card slot-element"
     data-context-type="card"
     data-context-id="179"
     style="--card-bg-color: #574b81;
            --card-border-color: #574b81;
            --slot-position: 21;
            --slot-size: 12;">
  ...
</div>
```

В таблице стилей сетки определены базовые метрики:
```css
:root {
  --interval-minutes: 15;
  --interval-height: 20px;
  --minute-height: calc(var(--interval-height) / var(--interval-minutes)); /* 1.3333px */
}

.scheduler-card {
  position: absolute;
  left: 2px;
  right: 2px;
  top: calc(var(--slot-position) * var(--interval-height));
  height: calc(var(--slot-size) * var(--interval-height));
  background-color: var(--card-bg-color);
  border-left: 4px solid var(--card-border-color);
  border-radius: 6px;
  box-sizing: border-box;
  transition: transform 0.15s ease, box-shadow 0.15s ease;
}
```

### 3.2. Преимущества архитектуры
1. **Zero Layout Thrashing:** Изменение масштаба сетки (например, переключение с шага 15 мин на 30 мин или изменение плотности с 20px на 28px) выполняется мгновенной сменой одной переменной `--interval-height` на родительском контейнере без пересчета координат сотен элементов в DOM.
2. **GPU Acceleration:** Анимации Drag-and-Drop и подсветка слотов используют композитные слои.
3. **Изоляция коллизий:** Проверка пересечения карточек выполняется дискретно по целочисленным индексам слотов:
   $$\text{SlotStart}_A < \text{SlotEnd}_B \quad \land \quad \text{SlotEnd}_A > \text{SlotStart}_B$$

## 5. ЭРГОНОМИЧЕСКИЙ ПРОРЫВ: ВЫДВИЖНОЙ DRAWER И УМНЫЙ АВТОПОДБОР СЛОТОВ («НАЙТИ ВАРИАНТЫ»)

### 5.1. Пошаговый флоу создания записи без перекрытия экрана
В старых CRM (и в expo25) кнопка «+ Запись» открывала модальное окно поверх всей сетки, блокируя обзор других врачей. В expo26 при нажатии кнопки `+ Добавить запись` левый сайдбар (где отображаются задачи обзвона) плавно трансформируется в **панель «Запись пациента»**:

1. **Мгновенный предиктивный поиск:**
   - Поле ввода принимает ФИО или последние цифры телефона.
   - Выпадающий список подтягивает возраст пациента, маскированный телефон (`+..........7`), баланс и **золотую иконку короны** (VIP/постоянный клиент).
2. **Сегментированный переключатель статуса визита:**
   - Три взаимоисключающие кнопки на единой подложке: `[Плановый] | [Внеплановый] | [Утверждённый]`.
   - `Внеплановый` автоматически присваивает признак CITO (острая боль) и подсвечивает карточку ярким контуром.
3. **Киллер-фича: Кнопка «Найти варианты»:**
   - Вместо того чтобы регистратор вручную листал недели и проверял расписание каждого ортопеда, система сама запрашивает бэкенд по критериям (Специализация + Длительность + Филиал) и выдает ранжированный список свободных окон.
   - Клик по найденному варианту автоматически позиционирует карточку в нужную колонку и закрывает шторку.

## 6. КОНТЕКСТНЫЙ МИКРО-HUD КЛИНИЧЕСКИХ ДЕЙСТВИЙ (1-CLICK SPEED LOOP)

При клике на любую карточку приема в сетке в правом нижнем углу экрана всплывает компактный HUD ([`50_card_179_clicked.png`](file:///C:/Clinic_MVP/dental-crm/docs/competitive-audit/РЕВЕРС%20ИНЖИНИРИНГ%20DENTALPRO/expo26_new_schedule/screenshots/50_card_179_clicked.png)):
- Шапка с полным ФИО, возрастом, номером карты, филиалом, врачом и назначенным креслом.
- Нижний ряд из **6 мгновенных кнопок-действий**, исключающих блуждание по боковому меню:
  1. `Амбулаторная карта` — прямой переход в ЭМК 043/у к дневнику приёма.
  2. `Запланировать посещение` — быстрая запись на следующий прием к этому же врачу через N дней.
  3. `Заполнить анкету` — опросник соматического статуса и аллергоанамнеза.
  4. `План лечения` — переход к смете и этапам комплексного плана.
  5. `Результат посещения` — протокол оказанных услуг для списания материалов и печати акта.
  6. `В лист ожидания` — перемещение пациента в буфер ожидания при отмене визита.

## 7. РЕЗЕРВЫ, БЛОКИРОВКИ И ВРАЧЕБНЫЕ СМЕНЫ

В сетке expo26 четко визуализированы 3 категории неклинического времени:
1. **Планерка / Собрание (09:00 - 09:15):** Желтая карточка с пунктирной рамкой `border: 1px dashed #f59e0b`. Запрещает посадку пациентов.
2. **Обед (13:00 - 14:00):** Желтый блок с центрированной подписью и иконкой блокировки.
3. **Нерабочие часы смены (14:00 - 21:00):** Серый фоновый паттерн с иконкой замка `slot-element-blocked` (`--block-color: rgb(145, 145, 145)`). Врач физически не принимает. При наведении на такой блок появляется кнопка `+` для экстренного открытия смены администратором.

## 8. ЭКОСИСТЕМА СМЕЖНЫХ МОДУЛЕЙ DENTALPRO EXPO26

В ходе проактивного радара были исследованы и задокументированы сопутствующие модули экосистемы:
1. **Интеграция с визиографами и КТ Vatech EzDent-i:** Прямой вызов нативного просмотрщика снимков по протоколу URI scheme (`vatech://patient?id=...`).
2. **Apple Wallet (.pkpass):** В карточке пациента доступна кнопка «Выдать карту Apple Wallet» со штрихкодом лояльности и push-уведомлениями о визитах.
3. **Мультикошельковая касса (9 балансов):**
   - Собственные средства
   - Персональный счет
   - Заёмный счёт (рассрочка клиники)
   - Долг
   - Доступно в долг (лимит доверия)
   - Не оплачено
   - Целевые авансы (под ортодонтию/ортопедию)
   - Страховые счета (ДМС)
   - Корпоративные счета (договоры юрлиц)
4. **Складской учет номенклатуры:** Строгий партионный учет дорогостоящих имплантационных систем (Straumann, Medentika, Anthogyr) с привязкой артикулов и штрихкодов к актам списания.

## 9. RED TEAM АУДИТ ДЕФЕКТОВ DENTALPRO (ЧТО СДЕЛАНО ПЛОХО)

Несмотря на визуальный прогресс, в архитектуре DentalPRO expo26 вскрыты серьезные инженерные дефекты, которые **категорически запрещено повторять в DENTE**:

1. 🚨 **Чудовищный монолит бандла (5.1 МБ vendor.js):**
   - В один бандл скомпилированы устаревший редактор Froala, Moment.js, Day.js, CanvasJS, jQuery-плагины и React. Время первой загрузки на слабых ПК администраторов достигает 4–6 секунд.
   - *Решение для DENTE:* Чистый современный Vite-бандл на React 19 с динамическими импортами (`React.lazy`). Размер бандла расписания в DENTE — менее 350 КБ.
2. 🚨 **Отсутствие недели и кресельной сетки на проде (404 ошибки):**
   - Роуты `/schedule/week` и многие служебные вкладки отдают ошибку 404 «Страница не найдена». Функционал находится в состоянии незавершенного MVP.
3. 🚨 **HTML5 Drag-and-Drop без поддержки тач-интерфейсов:**
   - Реализация DnD через события `dragstart`/`dragover` не работает на планшетах iPad у кресла врача.
   - *Решение для DENTE:* В DENTE используется единая модель на Pointer Events с хитбоксами под пальцы в перчатках (Мандат 8c).
4. 🚨 **Модальный спагетти-код из легаси-PHP:**
   - Часть всплывающих окон по-прежнему вызывается через устаревший `mivio.alertRemote` с инъекцией нетипизированного HTML, порождая потенциальные XSS-уязвимости и рассинхрон со стором React.

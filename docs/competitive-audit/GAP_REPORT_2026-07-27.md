## 1. Главная находка: слой «фич» существовал только на экране

В коде было 114 таблиц, 65 модулей доступа к данным и 56 виджетов, названия которых
один в один повторяют пункты списка возможностей IDENT: `ndfl_tax_calculators`,
`uis_sms_chat_quotas`, `confirmation_performance_reports`, `diagnocat_ai_findings`,
`egisz_blank_permissions`, `patient_archive_reasons_and_blacklists` и так далее.

Все они были устроены одинаково:

```ts
export async function getXFromDb(orgId) {
  try {
    await ensureXTable();                       // CREATE TABLE во время запроса
    const rows = await db.select().from(X)...;
    if (rows && rows.length > 0) return rows;   // только НЕПУСТОЙ результат
  } catch (err) {
    console.warn("[X DB Fallback]:", err);      // ошибка проглатывается
  }
  return [ { patientName: "Орлов Станислав Викторович", ... } ];
}
```

Проверка на живой базе: **все таблицы этих модулей пусты (0 строк)**. То есть каждый
такой экран показывал выдуманных пациентов с диагнозами и суммами, неотличимых от
настоящих данных. У 17 таблиц набор колонок в рантайм-DDL расходился с `db/schema.ts`,
поэтому запрос падал на уровне SQL всегда — и наружу шли те же выдумки.

Виджет — это список на чтение. Ни расчётов, ни записи, ни кнопок действия.
Например `NdflTaxCalculatorsWidget` назван «Авто-Калькулятор Справки НДФЛ с Блокировкой
при Аномалиях», но ничего не считает и ничего не блокирует: рисует три поля из
подставного ответа. В IDENT эта функция — кнопка «Вставить», которая подставляет сумму
в документ и блокируется с объяснением причины (долг, товар, доп. касса).

**Сделано:** удалены 51 рантайм-DDL и 53 её вызова, 51 геттер переписан на прямой
возврат результата, из 56 виджетов убран жёстко зашитый идентификатор организации.
Пустая таблица теперь даёт пустой список, сбой базы — ошибку. Поставлен тест
`noFabricatedDataFallback.test.ts`, который не даёт вернуть этот приём.

**Следствие для планирования:** ни одну строку из `FEATURES_REGISTRY.md` со статусом
«есть» нельзя принимать без проверки на живых данных.

4. **Планы лечения до уровня IDENT.** Этапы, закрепление цен, режимы скидок, перенос
   услуг в наряд. Ядро расчёта уже есть и написано аккуратно.

   транспорта в N3.Health. Это обязательное требование, а не конкурентное
   преимущество.
6. **Довести права доступа.** Матрица есть, включена на денежных маршрутах в мягком
   режиме. Следующий шаг — обязательный вход сотрудника и `requirePermission` на всех
   изменяющих маршрутах.

в том, что за ними стоит.

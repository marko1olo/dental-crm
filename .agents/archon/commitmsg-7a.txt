[ARCHON] fix(оркестрация): агенты гоняли общий гейт параллельно — исправлено по §7a конституции

Конституция дополнена по ходу кампании: .agents/AGENTS.md §7a «One writer per gate». Правило
прямое: npm run typecheck, npm run build, миграции, сиды и прогоны Playwright трогают общее
состояние — dist/, apps/web/tsconfig.tsbuildinfo, сгенерированный packages/shared/dist/ и
единственный живой PostgreSQL на 127.0.0.1:5432. Один агент за раз.

Я это нарушал. В каждой волне три-четыре агента одновременно выполняли
npm run typecheck -w @dental/web, а эта команда ПИШЕТ apps/web/tsconfig.tsbuildinfo. Вероятный
источник шума в результатах: агент видел ошибки, которых в его файлах не было, и тратил на них
время.

Скрипт седьмого цикла приведён в соответствие:
- агентам запрещены typecheck, build, прогон всего набора тестов, миграции и сиды;
- их собственный сигнал — один свой тестовый файл через node --import tsx --test, он не
  трогает общее состояние сборки;
- если пакету действительно нужна сборка или миграция, он обязан остановиться и записать это
  в blockers, а исключительный доступ выдаёт ведущий;
- ведущий гоняет общие ворота последовательно в конце волны.

Заодно в каждое задание добавлены обязательные по §7a поля: роль, причина делегирования,
владеемая область правки, ЗАПРЕЩЁННАЯ область, стандарт доказательства и прямое указание, что
вывод субагента — доказательство, а не полномочие.

И устранено противоречие, накопившееся в переиспользуемой преамбуле. Мой срез «LAW» из шестого
цикла затянул внутрь себя поправки пятого, поэтому в промпте одновременно жили старое «можешь
свободно собирать» и новое «сборка не твоя», плюс мёртвое упоминание шести ошибок AnamnesisField,
которых больше нет. Добавлен явный список отменённых утверждений: противоречивые указания в
одном промпте — прямая причина того, что агент делает не то.

ПРОВЕРЕНО: оба общих гейта прогнаны мной последовательно, как и предписывает §7a —
npm run typecheck -w @dental/api и -w @dental/web, по нулю ошибок TS в каждом.

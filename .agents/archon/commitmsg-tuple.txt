[ARCHON] fix(деньги): график рассрочки не компилировался — тип splitKopecks не выражал собственную гарантию

HEAD БЫЛ КРАСНЫМ, И ЭТО НАДО СКАЗАТЬ ПРЯМО. Пакет Z1 закоммитил ca7dbeed8 и умер на кредитах до
того, как ревьюер до него добрался. Коммит не компилировался: npm run typecheck -w @dental/api давал
три ошибки в apps/api/src/documents/renderDocument.ts на строках 837, 840 и 843. Файл при этом чист
в рабочем дереве, то есть красным был не мой черновик, а история. Проверено разделением: сломанные
файлы веба грязные (незавершённая миграция контракта живого агента), а этот — нет.

ПРИЧИНА, И ОНА НЕ В ВЫЗЫВАЮЩЕМ КОДЕ. splitKopecks в packages/shared/src/utils/money.ts объявлял
возврат как Kopecks[]. При включённом noUncheckedIndexedAccess разбор
`const [first, second] = splitKopecks(remaining, 2)` даёт Kopecks | undefined для ОБЕИХ частей, хотя
функция сама отсекает parts меньше единицы броском. То есть тип не выражал гарантию, которую функция
уже обеспечивает, и вызывающий был обязан проверять то, чего не бывает.

ЧИНЮ В ИСТОЧНИКЕ, НЕ НА ВЫЗОВЕ. Возврат теперь непустой кортеж [Kopecks, ...Kopecks[]]. Это не
украшение и не подгонка под компилятор: при parts >= 1 первая часть существует всегда, и утверждение
верно для любого будущего вызывающего. Вторая часть по-прежнему может отсутствовать — при parts: 1 её
действительно нет, и тип обязан эту правду сохранить, поэтому на вызове стоит значение по умолчанию
ноль, а не подавление ошибки. Условие ниже уже отбрасывало нулевой финальный платёж, так что поведение
не изменилось ни на копейку — изменилась только честность типа.

Альтернативу «поставить `!` или `?? 0` на вызове» отклонил: она гасит ошибку в одном месте и оставляет
её для второго вызывающего, которого ещё нет. Правило кампании — предпочитать выводимые типы
скопированным утверждениям — здесь применимо буквально.

ЗАОДНО СНЯТА СКРЫТАЯ ЛОВУШКА, СТОИВШАЯ МНЕ ОДНОГО ЛОЖНОГО ЗАМЕРА. После правки исходника
packages/shared api ВСЁ ЕЩЁ показывал ошибку: он импортирует из собранного packages/shared/dist, а не
из исходника. Первый прогон typecheck после правки отдал 1 ошибку и относился к прошлому состоянию
кода — ровно тот класс подделки доказательства, против которого построен страж свежести сборки в
маршрутном гейте. Сборка @dental/shared — общий гейт по §7a, значит мой; выполнил, после чего api
даёт 0 ошибок.

ПРОВЕРЕНО: npm run build -w @dental/shared выход 0; npm run typecheck -w @dental/api выход 0,
0 ошибок. НЕ ПРОВЕРЕНО этой правкой: веб-гейт остаётся красным по другой причине — незавершённая
миграция контракта panelStateText, где мёртвый агент сменил общий тип и не обновил семь потребителей
и собственный тест. Это отдельная работа, и §10 требует довести её синхронно, а не откатить: замена
title на notLoadedTitle убирает «Статус не загружены», а retryLabel убирает кнопку «Повторить» рядом
с текстом, где повтор не поможет никогда.

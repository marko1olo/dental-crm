[ARCHON] fix(прайс): английский текст модели доезжал до экрана русской клиники — закрыто с двух сторон

ТРЕТИЙ ЭКЗЕМПЛЯР ОДНОГО КЛАССА в этом файле. Первые два — crownType («unknown», «zirconia crown») и brand,
оба через тот же путь: свободная строка из модели печатается как есть. Находка ревьюера волны OO, перемерена
ведущим ИСПОЛНЕНИЕМ функции подписи, а не чтением.

ЗАМЕР ДО ПОЧИНКИ, вывод pricelistWarningsText дословно:
  "price_ambiguous"        → «price ambiguous»
  "two_prices_in_one_row"  → «two prices in one row»
  "totally_made_up_key"    → «totally made up key»
То есть ЛЮБОЙ незнакомый ключ печатался клинике английскими словами в её собственном прайсе.

ПУТЬ УТЕЧКИ. itemFromGroq сливает asWarnings(record.warnings) от модели с предупреждениями разбора
(analyzer.ts:1791), а groqSystemPrompt перечисляет допустимые значения для ПЯТИ полей и про warnings не
говорит НИЧЕГО. Значит модель вправе прислать любую строку. На стороне интерфейса последняя ветка подписи
была `pricelistWarningLabels[normalized] ?? normalized.replace(/[_-]+/g, " ")` — сырой ключ через пробелы.

ЗАКРЫТО ДВУМЯ РУБЕЖАМИ, потому что одного мало: белый список не знает будущих ключей разбора, а подпись не
знает, откуда ключ пришёл.

1. ПРИЧИНА — белый список на разборе (analyzer.ts, asWarnings). Пропускаются ровно те ключи, которые ставит
   сам разбор (buildWarnings): price_not_found, category_uncertain, material_uncertain,
   restoration_uncertain, title_too_short, photo_ocr_requires_visual_review. Отличить «наш ключ, которого мы
   ещё не знаем» от выдумки модели по ФОРМЕ нельзя — только по списку.
   НЕЗНАКОМОЕ НЕ ТЕРЯЕТСЯ МОЛЧА: вместо выброшенных ключей ставится material_uncertain, то есть строка
   остаётся помеченной «проверьте руками». Тихо выбросить просьбу модели проверить строку было бы ХУЖЕ, чем
   показать чужой ключ: просьба исчезла бы вместе с ключом, а это ровно тот класс молчаливой потери, против
   которого написан весь этот файл.

2. ЭКРАН — честная фраза вместо имени ключа (pricelistUiMeta.ts). Клинике важно не имя ключа, а что делать
   со строкой. Сам ключ не теряется: он остаётся в item.warnings ответа.

ЗАМЕР ПОСЛЕ, подпись:
  "price_ambiguous"           → «Строку нужно проверить руками»
  "two_prices_in_one_row"     → «Строку нужно проверить руками»
  "totally_made_up_key"       → «Строку нужно проверить руками»
  "material_uncertain"        → «Материал требует проверки»            без изменений
  "price_not_found"           → «Цена не найдена»                      без изменений
  "groq_failed:boom"          → «Нейро-проверка прайса недоступна»      без изменений
  "pricelist_rows_skipped:3"  → «Строк не признано услугами: 3 — проверьте прайс»  без изменений

ЗАМЕР ПОСЛЕ, белый список (зонд scratch/probe-model-warnings.ts, приложен, через itemFromGroq напрямую —
он экспортирован именно для такой проверки, потому что ветка Groq здесь не исполняется):
  выдумка модели         → ["material_uncertain"]                       английский выброшен, просьба цела
  выдумка + известное    → ["price_not_found","material_uncertain"]      известное сохранено
  только известные       → ["price_not_found","category_uncertain"]      без изменений
  не массив              → []

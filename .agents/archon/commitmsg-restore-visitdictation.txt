[ARCHON] fix(сборка): HEAD не собирался — VisitView импортировал удалённый VisitDictation

Возврат файла apps/web/src/components/visit/VisitDictation.tsx, удалённого по ошибке
в 068cc6f0c.

ЧТО ПРОИЗОШЛО. Индекс git — общее состояние на весь репозиторий, а не личное
пространство агента. В дереве параллельно работает второй автор: он выполнил
`git rm apps/web/src/components/visit/VisitDictation.tsx` (эта команда индексирует
удаление немедленно) и правил apps/web/src/VisitView.tsx, собираясь закоммитить оба
изменения вместе. Между этими двумя шагами коммит агента [ARCHON] по совершенно
другой задаче забрал из индекса чужое удаление — потому что `git commit` без списка
путей коммитит весь индекс целиком.

ПОЧЕМУ ЭТО СЛОМАЛО СБОРКУ. В закоммиченной версии VisitView.tsx строка 24 —
`import { VisitDictation } from "./components/visit/VisitDictation";`, строка 337 —
`<VisitDictation />`. Сам файл на HEAD уже отсутствовал. То есть на чистом клоне
`npm run typecheck -w @dental/web` падал бы; рабочее дерево этого не показывало,
потому что там лежит несохранённая правка второго автора, которая импорт убирает.

ПОЧЕМУ ВОЗВРАТ, А НЕ ПЕРЕПИСЫВАНИЕ ИСТОРИИ. В ветку каждые несколько минут коммитит
другой автор, и часть коммитов уже отправлена. Переписывание общей истории здесь
опаснее самой поломки. Файл возвращён отдельным коммитом; история остаётся линейной
и собираемой на каждом коммите.

ЧТО ДАЛЬШЕ. Удаление VisitDictation.tsx само по себе выглядит осмысленным — второй
автор убирает вторую диктовку на том же экране, о чём прямо говорит комментарий в его
правке VisitView.tsx. Это удаление должно вернуться вместе с правкой VisitView.tsx,
одним коммитом, а не по частям. Ничего из несохранённой работы второго автора здесь
не тронуто.

ПРОЦЕДУРНОЕ ИСПРАВЛЕНИЕ. Все коммиты флота переведены на форму
`git commit -F <msg> -- <явные пути>`: список путей ограничивает коммит независимо от
того, что ещё лежит в общем индексе.

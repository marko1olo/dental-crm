[ARCHON] chore(сборка): apps/api/dist больше не отслеживается — в git лежала уязвимая сборка

Из индекса убраны 149 артефактов сборки. .gitignore со второй строки содержит dist/, но
правило не действует на уже добавленные файлы, поэтому собранный код продолжал жить в
репозитории и устаревать.

ЧЕМ ЭТО БЫЛО ОПАСНО. apps/api/package.json объявляет "start": "node dist/server.js".
Закоммиченный dist/routes/speech.js был собран ДО правки диктовки: ноль вхождений нового
охранника, никакого предиката по организации на выборках. npm start обслуживал ту самую
уязвимую версию, которую в исходниках уже починили. Живой стенд уцелел лишь потому, что
Launcher.ps1 поднимает npm run dev.

ПОЧЕМУ БЕЗОПАСНО, ПРОВЕРЕНО ПЕРЕД УДАЛЕНИЕМ:
- apps/api/Dockerfile:30 сам выполняет npx turbo run build --filter=@dental/api и только
  затем CMD ["node", "dist/server.js"]. Контейнеру закоммиченная сборка не нужна.
- Четыре смоука, читающие apps/api/dist/server.js, требуют сборки явно и падают с текстом
  «Build API first: apps/api/dist/server.js is missing.»
- Рабочее дерево не тронуто: git rm -r --cached, файлы на диске остались.

Побочный выигрыш: уходит постоянный шум. Ревьюер, честно выполнявший npm run build как
доказательство, пачкал 44+ отслеживаемых файла и мешал каждому агенту отличать свои
изменения от чужих.

ОТДЕЛЬНО, ЧЕСТНО: предыдущая попытка b96f6d04e сделала обратное задуманному. Я вызвал
git rm -r --cached, а затем git commit со списком путей. Форма с путями фиксирует
состояние РАБОЧЕГО ДЕРЕВА этих путей, а файлы на диске остались, поэтому подготовленное
удаление было отменено и вместо него закоммичена пересобранная сборка. Та самая форма,
которой я защищаю флот от чужого индекса, здесь сработала против намерения. Правильный
порядок для снятия с учёта: git rm -r --cached, затем глазами проверить
git diff --cached --name-only, затем коммит БЕЗ списка путей.

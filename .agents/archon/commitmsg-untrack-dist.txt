[ARCHON] chore(сборка): из git убраны 149 файлов apps/api/dist — там лежала уязвимая сборка

apps/api/dist отслеживался git, хотя .gitignore со второй строки содержит dist/. Правило
.gitignore не действует на уже добавленные файлы, поэтому 149 артефактов сборки жили в
репозитории и устаревали.

ЧЕМ ЭТО ОПАСНО, А НЕ ПРОСТО НЕОПРЯТНО. apps/api/package.json объявляет
"start": "node dist/server.js". Закоммиченный dist/routes/speech.js был собран ДО правки
диктовки: в нём ноль вхождений нового охранника и нет предиката по организации на
выборках. То есть npm start обслуживал именно ту уязвимую версию, которую в исходниках
уже починили. Живой стенд был в порядке только потому, что Launcher.ps1 поднимает
npm run dev, а не npm start.

ПОЧЕМУ УБИРАТЬ БЕЗОПАСНО, ПРОВЕРЕНО:
- apps/api/Dockerfile строка 30 сам выполняет npx turbo run build --filter=@dental/api и
  только потом CMD ["node", "dist/server.js"]. Контейнеру закоммиченная сборка не нужна.
- Четыре смоука, читающие apps/api/dist/server.js, требуют сборки явно и падают с текстом
  «Build API first: apps/api/dist/server.js is missing.» — они и так рассчитывают на build.
- Рабочее дерево не тронуто: применено git rm -r --cached, файлы на диске остались.

Побочный выигрыш: пропадает постоянный шум. Любой ревьюер, честно выполнивший
npm run build как доказательство, пачкал 44+ отслеживаемых файла, и это мешало каждому
агенту отличать свои изменения от чужих.

Отныне клон без сборки упадёт на npm start громко и понятно, вместо того чтобы тихо
поднять устаревший уязвимый сервер.

[ARCHON] fix(безопасность): баннер загрузки перечислял послабление «код портала 0000», которого нет

apps/api/src/server.ts:115 безусловно печатал «код портала по умолчанию 0000» в списке
активных послаблений режима разработки. Соседние записи в этом списке зависят от флагов
окружения, а эта стояла всегда.

Утверждение перестало быть правдой ещё в цикле 1. configuredPortalOtpCode() больше не
возвращает общий статический код: портал выдаёт одноразовый код на каждый запрос, хранит
только его хэш, ограничивает попытки и отвечает 401 на «0000». Проверено живым запросом:
POST /api/portal/auth/verify-otp с кодом «0000» -> HTTP 401.

ПОЧЕМУ ЭТО ДЕФЕКТ, А НЕ ОПЕЧАТКА. Оператор читает эту строку при загрузке, чтобы понять
риск конкретного стенда. Он получал список, не совпадающий с поведением сервера. Это тот
же класс, что и остальные находки кампании: продукт утверждает то, чего не делает. Причём
комментарий прямо над списком объясняет, что сообщение как раз и переделывали ради
«фактического состояния» — а эту запись забыли.

Заменено на настоящее оставшееся послабление, с точной ссылкой на условие: при
NODE_ENV != "production" и ненастроенной отправке SMS одноразовый код уходит в лог
сервера (routes/portal.ts:270, developerLogFallback) и никогда не попадает в тело ответа.

ПРОВЕРЕНО. npm run typecheck -w @dental/api — 0 ошибок. npm run build -w @dental/api —
выход 0, мусора в git ноль. Баннер после пересборки:
«Активные послабления: демо-вход, код входа в портал пишется в лог сервера, пока у клиники
не настроена отправка SMS». Живой запрос с «0000» по-прежнему 401.

НАЙДЕНО ПОПУТНО, НЕ ЧИНИЛ: новый поведенческий гейт маршрутов сообщает, что
POST /api/auth/clinic/set-password и POST /api/auth/staff/set-pin проверяют тело запроса
до проверки прав (auth.ts:278-281 против 283-292 и auth.ts:331-337 против 339-348).

[ARCHON] «не определяется» больше не печатается нулём: деньги переноса, акт сверки, график рассрочки

Один класс дефекта в пяти местах apps/api: `?? 0` на значении, которого НЕТ. Отсутствие
становилось нулём, ноль от измеренного не отличался ничем и печатался клинике как факт.

1. migration/engine.ts + новый migration/sourceMoney.ts — сумма платежей источника.
   Было `sum + (parsedAmount.value ?? 0)`: значение, которое суммой не является («оплата
   по договору» в колонке суммы), давало value === null и входило в итог нулём. Это число
   уходит в сверку как НЕЗАВИСИМАЯ точка отсчёта, и подставленный ноль убивал именно её:
   строка с неразобранной суммой не попадает ни в одну из сторон баланса (в стейджинге
   amountKopecks у неё null, SQL-сумма её пропускает), обе стороны теряли одни и те же
   деньги на одну и ту же величину, разность выходила ровно 0 — и акт переноса печатал
   «Сумма платежей источника 24 901,50 ₽ разобрана полностью, копейка в копейку» про
   перенос, где часть денег не разобралась вовсе. Проверка не могла провалиться.
   Теперь: хотя бы одно нечитаемое значение — сумма null, оператор получает
   предупреждение с числом таких значений и именем колонки. Пустая колонка (source прямо
   говорит «суммы нет») сумму не отравляет, но если не заполнено ни одно значение — тоже
   null: складывать нечего. Расчёт вынесен в модуль без обращений к базе, иначе денежное
   правило нельзя проверить без живого PostgreSQL.

2. migration/engine.ts, runMigration — тот же дефект на уровень выше: из двух таблиц с
   платежами неопределимая входила в итог прогона слагаемым 0.

3. migration/phases.ts, finishRunPhase — в sourceMoneyTotalKopecks подставлялся
   stagedMoneyKopecks(runId), то есть РОВНО ТО ЖЕ выражение, которым сверка считает вторую
   сторону баланса. Проверка сравнивала стейджинг сам с собой: разность тождественно 0,
   passed всегда true. Докстринг reconcile.ts запрещает именно это. Независимой суммы у
   потокового пути сегодня нет — значит null, а не подставленное число. У
   runStore.stagedMoneyKopecks теперь стоит предупреждение, чтобы её не вернули обратно.

4. migration/reconcile.ts, акт для клиники — весь денежный раздел стоял под
   `if (report.sourceMoneyTotalRub !== null)`: вместе с неопределившейся суммой источника
   из акта исчезали ИЗМЕРЕННЫЕ «Загружено» и «В карантине». Клиника подписывала акт, где
   про деньги не сказано ничего. Теперь суммы печатаются всегда, неизвестная — словами
   «не определяется» (пустая клетка в CSV неотличима от нуля), плюс строка о том, что
   проверка полноты денег НЕ ВЫПОЛНЯЛАСЬ.

5. documents/renderDocument.ts, график рассрочки на руки пациенту — `?? 0` на сумме плана
   давал остаток `max(0, 0 - оплачено)` = 0, и документ печатал «План полностью оплачен —
   0 руб.» про план с неизвестной стоимостью; строкой выше «Общая сумма плана» честно
   печаталась как «не указана». Остаток теперь null → «не указана», а таблица платежей
   называет причину. Строка «Оплачено: 0 руб.» осталась: это измеренный ноль.

6. routes/imaging.ts — отсутствующий тег DICOM (0028,0103) отдавался в ответ как 0, а ноль
   в этом теге означает «беззнаковые значения пикселей», то есть измеренный факт. Ветка
   unsupported на тот же отсутствующий тег отвечала null. Контракт допускает null
   (nullable в packages/shared). Выбор отрисовщика не тронут: он читает metadata напрямую.

Доказательство: apps/api/src/tests/unknownIsNotZero.test.ts, 8 тестов, выход 0.
Проверяется не наличие правки, а поведение: сумма источника с нечитаемым значением обязана
быть null (и тест хранит измеренное прежнее число 350050 копеек, которое печаталось), акт
обязан содержать «Сумма в источнике;не определяется» вместе с непустым «Загружено», строка
«Остаток» в графике обязана быть «не указана», а не «0 руб.». Обратная сторона проверена
тем же прогоном: известные суммы печатаются как раньше, «Оплачено: 0 руб.» не тронуто.

### F1 (HIGH) — `data.contour.closed` объявлен и не читается: панорама отрастает хвост

`apps/web/src/components/dicom/panoramicArch.ts:46` (до правки) описывал `closed?: boolean`.
`rg -n "closed" apps/web/src/components/dicom/panoramicArch.ts` возвращал ровно одну строку — саму
декларацию. Ни одна строка кода флаг не читала.

Цепочка (проверена в установленном cornerstone, не по пересказу):
- `SplineROITool.js:245-269` — закончить обводку можно только замкнув её: двойной клик или клик по
  первой точке ставят `data.contour.closed = true`, после чего вызывается `_endCallback`. Единственный
  другой выход — ESC/backspace, то есть `cancel()` с удалением аннотации.
- `SplineROITool.js:767` — `spline.closed = !!data.contour.closed`.
- `CubicSpline.js:40-44` — у замкнутого сплайна число сегментов равно числу точек, у открытого на
  один меньше; `Spline.js:211-214` отдаёт polyline по всем сегментам.
- `SplineROITool.js:599-603` + `updateContourPolyline.js` — именно эта polyline уезжает в
  `data.contour.polyline`.
- `panoramicArch.ts:384-387` (до правки) предпочитал polyline всегда, когда она плотнее списка точек,
  то есть практически всегда, и `resamplePolylineByArcLength` шёл по ней как по ОТКРЫТОЙ кривой.

Замер на живом cornerstone 5.1.3 (те же 7 точек, `CatmullRomSpline`):
открытая polyline — 127 точек / 91.968 мм; та же кривая с `closed = true` — 148 точек / 155.288 мм и
конец снова в `(-28, 11)`. **40.8% длины развёртки было обратным проходом через язык и небо**, и на
столько же завышалась «длина дуги» в плашке — единственное число, которым панорама подтверждала свою
подлинность. Ревью оценивало ~30%; фактически хуже.

Отягчающее (ревью право): фикстура пиновала случай, которого в продакшене не бывает —
`panoramicArch.test.ts:49` жёстко ставил `closed: false`.

### F2 (HIGH) — `voxelManager.getScalarData()` бросает на каждом реальном объёме КЛКТ

`Cornerstone3DViewer.tsx:294-296` (до правки) вызывал `volume?.voxelManager?.getScalarData()` вне
`try/catch` (он охватывал только `getAnnotations`, `:267-278`).

`VoxelManager.js:273-286` — `getScalarData()` заканчивается
`throw new Error('No scalar data available')`, если нет ни `scalarData`, ни `_getScalarData`.
`VoxelManager.createImageVolumeVoxelManager` (`VoxelManager.js:505-597`) не заполняет ни того, ни
другого: он ставит только `_getScalarDataLength` (`:636`), `getCompleteScalarDataArray` (`:643-669`) и
несколько срезовых аксессоров. Заполнить `scalarData` может только `setScalarData()`, которого на этом
пути никто не зовёт.

Следствия, которые ревью назвало и которые подтвердились: половина проверки `!raw` была недостижимым
кодом; исключение вылетало из `onClick` (React 18 не отправляет такое в error boundary), поэтому
кнопка «Развернуть» не давала ни панорамы, ни сообщения; и **закрывающая команда самого пакета C5 не
могла пройти ни при каких данных**.

Замер на живом cornerstone 5.1.3 (см. ПРОВЕРЕНО): `getScalarData()` бросает даже когда все срезы
декодированы и лежат в кэше изображений. То есть панорама не строилась ни до C5, ни после него.

- **F1.** `buildPanoramicArch` читает `data.contour.closed`. Для замкнутого контура polyline не

  0.3879 мм — меньше двух вокселей КЛКТ. Плюс cornerstone по умолчанию сам рисует Catmull-Rom
  (`SplineROITool.js:81`), то есть это то же семейство кривых, а не другая геометрия.

  лежат отказы.

6. **Многокомпонентные объёмы.** `readVolumeScalarData` принимает буфер длиной `>= dx*dy*dz`, а
   `trilinearInterpolate` индексирует объём как односкалярный. Для КЛКТ (один компонент) это верно;
   для RGB-объёма индексация была бы неверной и до моей правки, и после. Не трогал.
7. **Весь `Cornerstone3DViewer.tsx`** — инлайновые стили и статические hex (`#0a0a0a`, `#fff`,
   `#2563eb`, …), тема не переключается. Я добавил только токены в плашку.

### F1 (HIGH) — `data.contour.closed` объявлен и не читается: панорама отрастает хвост

`apps/web/src/components/dicom/panoramicArch.ts:46` (до правки) описывал `closed?: boolean`.
`rg -n "closed" apps/web/src/components/dicom/panoramicArch.ts` возвращал ровно одну строку — саму
декларацию. Ни одна строка кода флаг не читала.

Цепочка (проверена в установленном cornerstone, не по пересказу):
- `SplineROITool.js:245-269` — закончить обводку можно только замкнув её: двойной клик или клик по
  первой точке ставят `data.contour.closed = true`, после чего вызывается `_endCallback`. Единственный
  другой выход — ESC/backspace, то есть `cancel()` с удалением аннотации.
- `SplineROITool.js:767` — `spline.closed = !!data.contour.closed`.
- `CubicSpline.js:40-44` — у замкнутого сплайна число сегментов равно числу точек, у открытого на
  один меньше; `Spline.js:211-214` отдаёт polyline по всем сегментам.
- `SplineROITool.js:599-603` + `updateContourPolyline.js` — именно эта polyline уезжает в
  `data.contour.polyline`.
- `panoramicArch.ts:384-387` (до правки) предпочитал polyline всегда, когда она плотнее списка точек,
  то есть практически всегда, и `resamplePolylineByArcLength` шёл по ней как по ОТКРЫТОЙ кривой.

Замер на живом cornerstone 5.1.3, `CatmullRomSpline`, фикстура `archHandles(7)` из
`panoramicArch.test.ts` (см. ПОПРАВКИ ПАКЕТА S4 — прежние цифры этого абзаца отозваны, потому что
контрольные точки той пробы не были записаны):
открытая polyline — 127 точек / **90.8752 мм**; та же кривая с `closed = true` — 148 точек /
**154.2189 мм**, конец снова в `(-28, 11)`, зазор замыкания ровно 0. Обратный проход — 21 вершина и
**56.2250 мм, то есть 36.5% той polyline, по которой шёл код** (у `TRACED_ARCH`: 154 → 156.5652 /
99.1526 / 57.4126 мм = 36.7%). Настолько же завышалась «длина дуги» в плашке — единственное число,
которым панорама подтверждала свою подлинность. Ревью C5 оценивало ~30%; фактически хуже.

Отягчающее (ревью право): фикстура пиновала случай, которого в продакшене не бывает —
`panoramicArch.test.ts:49` жёстко ставил `closed: false`.

### F2 (HIGH) — `voxelManager.getScalarData()` бросает на каждом реальном объёме КЛКТ

`Cornerstone3DViewer.tsx:294-296` (до правки) вызывал `volume?.voxelManager?.getScalarData()` вне
`try/catch` (он охватывал только `getAnnotations`, `:267-278`).

`VoxelManager.js:273-286` — `getScalarData()` заканчивается
`throw new Error('No scalar data available')`, если нет ни `scalarData`, ни `_getScalarData`.
`VoxelManager.createImageVolumeVoxelManager` (`VoxelManager.js:505-597`) не заполняет ни того, ни
другого: он ставит только `_getScalarDataLength` (`:636`), `getCompleteScalarDataArray` (`:643-669`) и
несколько срезовых аксессоров. Заполнить `scalarData` может только `setScalarData()`, которого на этом
пути никто не зовёт.

Следствия, которые ревью назвало и которые подтвердились: половина проверки `!raw` была недостижимым
кодом; исключение вылетало из `onClick` (React 18 не отправляет такое в error boundary), поэтому
кнопка «Развернуть» не давала ни панорамы, ни сообщения; и **закрывающая команда самого пакета C5 не
могла пройти ни при каких данных**.

Замер на живом cornerstone 5.1.3 (см. ПРОВЕРЕНО): `getScalarData()` бросает даже когда все срезы
декодированы и лежат в кэше изображений. То есть панорама не строилась ни до C5, ни после него.

### `apps/web/src/components/dicom/panoramicArch.ts`

- **F1.** `buildPanoramicArch` читает `data.contour.closed`. Для замкнутого контура polyline не
  используется вообще: кривая интерполируется центростремительным Catmull-Rom по точкам врача — этот
  список открыт по построению. Вариант «вырезать замыкающий прогон» отвергнут сознательно: разрез по
  polyline — эвристика, а ошибка эвристики даёт ровно тот же класс дефекта (правдоподобная картинка с
  участком не той анатомии). Плюс cornerstone по умолчанию сам рисует Catmull-Rom
  (`SplineROITool.js:81`), то есть это то же семейство кривых, а не другая геометрия.

  **Цена этого отказа — ОТОЗВАНО И ПЕРЕИЗМЕРЕНО ПАКЕТОМ S4.** Прежняя формулировка
  («91.9670 мм против 91.9684 мм, 0.002%, максимальное отклонение 0.3879 мм — меньше двух вокселей
  КЛКТ») была неверна дважды и полностью снята; подробности и настоящие числа — в разделе
  «ПОПРАВКИ ПАКЕТА S4» ниже. Коротко, по замеру, который теперь исполняется как тест
  (`apps/web/src/tests/panoramicArchVsCornerstone.test.ts`): против кривой, которую врач видит на
  экране (дуговая часть ЗАМКНУТОЙ polyline), реконструкция короче на **7.26%** (`archHandles(7)`:
  97.9939 → 90.8755 мм) и **7.54%** (`TRACED_ARCH`: 99.1526 → 91.6748 мм), а максимальное отклонение
  столбца от неё — **4.0081 мм** и **4.0460 мм**, то есть порядка шестнадцати вокселей КЛКТ, а не
  «меньше двух». Плашка «длина дуги M мм» теперь занижает экранную дугу примерно на 7%: дефект F1
  был в том, что число завышалось обратным проходом, — теперь оно занижено концевым раздутием
  замкнутого сплайна. Знак другой, величина меньше, но это по-прежнему расхождение между
  единственным предъявляемым числом и тем, что нарисовано.

  **Почему геометрию всё равно не надо менять** (аргумент, которого в сдаче R2 не было). На фикстуре,
  чья истинная дуга известна аналитически (полуэллипс a = 28, b = 30, длина 91.1333 мм, сверено с
  формулой Рамануджана), реконструкция отклоняется от истины не более чем на **0.5802 мм**, а то, что
  cornerstone рисует для замкнутого контура, — на **3.6448 мм**, и переоценивает длину дуги на 7.5%.
  Интерполяция по точкам врача — самая точная из трёх кривых-кандидатов, в ~6 раз ближе к истине, чем
  экранная. Так что панорама СОЗНАТЕЛЬНО строится не по той кривой, которую видно на панели AXIAL, и
  это осознанный выигрыш в точности, а не побочный эффект.

  лежат отказы.
- **F2.** `readVolumeScalarData(volume, isSliceDecoded)` — правила готовности вокселей, описанные

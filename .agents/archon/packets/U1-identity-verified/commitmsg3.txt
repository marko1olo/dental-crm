[ARCHON] test(доступ): не было теста на запись по одному заголовку организации без токена

Дефект прожил столько, сколько прожил, потому что его никто не проверял: набор
tests/routes/* аутентифицируется именно заголовком x-organization-id, а
speechTranscribeChunkAccess.test.ts прямо удаляет DENTE_DEV_ALLOW_HEADER_ORG в
before, поэтому самый опасный случай не попадал ни в один прогон.

Тест поднимает НАСТОЯЩИЕ маршруты routes/clinical.ts дважды в одном процессе: одно
приложение слушает 127.0.0.1 на свободном порту и получает настоящие HTTP-запросы
через fetch, второе не слушает и вызывается через app.inject. Окружение самое
разрешающее из возможных: DENTE_DEV_ALLOW_HEADER_ORG=1,
DENTE_CLINICAL_ALLOW_UNGUARDED_MUTATIONS=1, ALLOW_UNGUARDED_READS=1, секрета
администратора нет. Если защита держалась бы на переменных окружения, проверки на
401 провалились бы.

Матрица: POST /api/clinical/rules по одному заголовку на живом сервере -> 401
UnverifiedOrganizationCannotMutate; POST /api/clinical/rules/evaluate так же -> 401;
запрос без заголовков вовсе -> 401 AuthRequired (код отказа обязан различать эти
два случая, иначе причину не найти); подписанный токен кабинета на том же живом
сервере -> 200; GET по заголовку -> 200; app.inject POST по заголовку на
неслушающем приложении -> 200, то есть tests/routes/* сохранены.

Проверки на 401 не обращаются к базе и выполняются всегда. Три проверки,
которым нужен PostgreSQL, помечаются skip при недоступной базе, а не выдают
зелёный результат за проверку, которой не было.

[ARCHON] fix(портал): в личный кабинет пациента пускал код «0000», один на всех

routes/portal.ts:53-56 при NODE_ENV != "production" возвращал `code || "0000"`,
а .env и .env.local задают NODE_ENV=development. На этой машине вход в личный
кабинет пациента открывался кодом «0000»: посторонний, знающий чужой номер
телефона, получал сессию на 12 часов и читал визиты, планы лечения, счета и
выданные документы. В production код брался из PORTAL_MVP_OTP_CODE — длиннее,
но по-прежнему ОДИН статичный секрет на всех пациентов навсегда.

Отправлять его при этом было нечем: POST /auth/send-otp отвечал
{ success: true, message: "OTP sent" } и не обращался ни к какому шлюзу.
Комментарий над этой строкой прямо это признавал.

Стало: код одноразовый, свой на каждый запрос и на каждого пациента.
- Выдаётся randomInt из node:crypto, шесть цифр.
- Живёт 300 с, гасится при первой успешной проверке (условный UPDATE, поэтому
  два одновременных запроса с верным кодом не дадут две сессии).
- Хранится только хешем PBKDF2-SHA512 (100k итераций, utils/cryptoHelper.ts).
  Проверка стоит 37.6 мс — ровно столько же, сколько уже платит вход клиники
  через verifyCredential, поэтому вторая схема хеширования не заводится.
- Потолок 5 попыток на код; на шестой код сжигается целиком и не примется даже
  верным. Счётчик растёт ДО сверки, иначе обрыв соединения дарит попытку.
- Не чаще одного кода в минуту и пяти в час на пациента: иначе кнопкой
  «отправить ещё раз» разоряют баланс шлюза.
- Уходит настоящей SMS через существующий транспорт: resolveChannelCredentials
  + sendThroughChannel, а не мимо него.

send-otp перестал врать. Ненастроенный шлюз — 503 с именами переменных, отказ
шлюза — 502 с классом ошибки. Ветка для разработки осталась, но недостижима при
NODE_ENV=production, генерирует свой код на каждый запрос и пишет его только в
журнал сервера — в теле ответа его нет.

Ответы send-otp и verify-otp намеренно неотличимы для «пациент найден», «номера
нет», «номер у двух карточек» и «код только что отправляли»: публичный маршрут
не должен работать справочником «лечится ли этот человек в клинике».

Локальная Map ограничения по IP удалена. Она дублировала уже работающее
глобальное правило security/rateLimit.ts на весь префикс /api/portal/ и при
этом никогда не очищалась — запись на каждый новый IP навсегда.

Новая таблица portal_otp_codes (drizzle/0133): код должен переживать перезапуск
и быть общим для воркеров, а счётчик попыток в памяти обнуляется рестартом,
то есть перебор снимался бы перезапуском. Ограничение CHECK на code_hash
(формат «соль:хеш», длина >= 96) делает запись открытого кода ошибкой БД.

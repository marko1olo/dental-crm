## Что было сломано

`scripts/smoke-visit-workflow-forms-lifecycle.mjs:529-533`. The dossier/brief citation of "line 531"
was ACCURATE as to location. It was WRONG about the nature and the scope:

- Brief said the file contained "U+FFFD replacement characters plus cp1252 mojibake". FALSE for this
  file. It had NO U+FFFD at all — only cp1252 mojibake. (The guard short-circuits per file: a U+FFFD
  hit `continue`s before the mojibake test, so a file reported as mojibake provably has no U+FFFD.)
- Brief implied fixing this one file would take the guard to exit 0. FALSE. The guard reports
  **28 problems across 28 files**. Mine was one of them.

The defect was not merely "a corrupted string". It was a **disabled assertion**:

    assert(
        issuedHtml.includes("<correct Russian: 'Otmetka o podpisanii'>") ||
            issuedHtml.includes("<the cp1252 double-encoding of that exact same string>"),
        `${formCase.kind}: HTML must include signature attestation block`,
    );

Operand B was byte-for-byte the mojibake of operand A. The assertion therefore read: *pass if the
product text is correct OR if it is corrupted.* It could not fail on the exact class of bug it is
named after — mojibake in a document handed to a patient. That is the same failure mode the guard
itself was written to catch after the 10,554-character telegram.ts incident.

Byte-level confirmation of operand B, from a codepoint dump before the edit: it contained an
invisible **U+0081** between the 9th and 10th glyphs. UTF-8 for Cyrillic "es" is `D1 81`; cp1252 has
no glyph for byte `0x81`, so it survived as a bare C1 control character. That detail is what proves
B was mechanically generated by a cp1252 misread and not typed by hand.

[ARCHON] перепись брошенных таблиц: «не определяется» больше не складывается в ноль, ссылки в api замеряются

Инструмент, по которому принимают решение об удалении таблиц с боевыми данными, печатал как
измеренное то, что не измерял. Два независимых дефекта, оба в решающей строке вывода.

1. АГРЕГАТ ПРЕВРАЩАЛ НЕИЗВЕСТНОЕ В НОЛЬ.
   Итоговая строка считала `results.reduce((n, r) => n + (r.rowsOutsideFixtures ?? 0), 0)`.
   У шести таблиц из восемнадцати нет колонки `organization_id` — среди них
   `payment_installments` и `signed_outpatient_cards`, то есть рассрочки платежей и подписанные
   амбулаторные карты. Для непустой таблицы без этой колонки «строк вне фикстур» честно равно
   null (в колонке так и печаталось: «не определяется»), а `?? 0` в итоге делал из него ноль.
   Сегодня вывод от этого не менялся, потому что все счёта нулевые. Но будь в
   `payment_installments` 500 строк, скрипт напечатал бы «непустых 1, строк вне фикстур 0» — а
   «строк вне фикстур» и есть критерий решения. Инструмент был готов подтвердить удаление
   боевой истории платежей.
   Теперь известное и неизвестное считаются отдельно (`summarizeRowsOutsideFixtures`) и
   печатаются по-разному: «известно N по K таблицам; НЕ ОПРЕДЕЛЯЕТСЯ ещё по M (имена) — в них
   X строк без колонки organization_id. Сумма НЕ полна; считать её нулём нельзя».
   В `--json` единого числа `rowsOutsideFixturesTotal` нет намеренно: пока есть таблицы без
   `organization_id`, единственного верного итога не существует.

2. ВНУТРИ ЗАМЕРА БЫЛИ ЧИСЛА, КОТОРЫЕ НИКТО НЕ МЕРИЛ.
   Колонка «ссылок в api» была набором констант `serverReferences`, вписанных руками, и стояла
   в выводе рядом с настоящими count(*) из базы. Их верность была свойством дня, когда их
   вписали: за время этого прогона другие агенты волны добавили в `apps/api/src` шесть файлов.
   Выбран замер, а не honest-подпись у констант: инструмент решает судьбу таблиц с данными,
   поэтому число обязано пересчитываться, а не гнить.
   `measureApiReferences` читает `apps/api/src` целиком и делит вхождения на четыре взаимно
   исключающих корзины: рабочий код, комментарии, тесты (код и комментарии теста). Сумма
   корзин сверяется с общим числом вхождений на каждом прогоне.
   Разделение — не косметика: `clinical_tasks` названа 18 раз, но это 5 обращений в рабочем
   коде, 5 упоминаний в прозе шапок и 8 ссылок из теста. Одно число «18» читалось как
   восемнадцать обращений к таблице. Опаснее обратный случай: таблица, названная только из
   теста или только в комментарии, при подсчёте одним числом выглядит живой и снимается с
   удаления без причины.
   Границы слова теперь с обеих сторон, а не только слева: `treatment_plan_stages` без правой
   границы ловится внутри `treatment_plan_stages_auto_archive`.
   Каталога исходников нет — печатается «не определяется», а не ноль.

САМОПРОВЕРКА `--selfcheck`, без базы. Свойство «неизвестное не становится нулём» на живой базе
сегодня не проверяется: все восемнадцать таблиц пусты, null не возникает ни разу, и сломанный
вариант печатает то же самое, что исправленный. Поэтому свойство проверяется на заданном
наборе, где неизвестное есть (500 строк рассрочек и 12 подписанных карт без колонки
организации), рядом печатается воспроизведённая старая строка, и отдельно проверяется новый
разборщик комментариев на образце с известным ответом — включая регулярку `/['"]/`, которая без
обработки регулярных литералов уводит разбор в мнимую строку.

ЗАМЕРЕНО (истинные коды возврата, без конвейера):
  node scripts/count-orphan-table-rows.mjs                                   → 0 (до и после)
  node scripts/count-orphan-table-rows.mjs --selfcheck                       → 0
  node scripts/count-orphan-table-rows.mjs --json                            → 0
  node --import tsx --test scripts/smoke-schema-missing-declarations.test.mjs → 0 (5/5)

Разбивка ссылок сверена с независимым `rg -P` по границе слова: `clinical_tasks` 5+5+8=18,
`patient_anamnesis` 1, остальные шестнадцать — ноль. Совпало по файлам и по корзинам.

БРИФ НЕВЕРЕН В ЧИСЛЕ: колонки `organization_id` нет у ШЕСТИ таблиц из восемнадцати, а не у
пяти. Шестая — `ztl_lab_orders`; в досье та же ошибка с другой стороны («13 из 18» вместо 12).

## FOUND

### 1. Тот же английский токен на том же экране, одно поле левее — `brand`. Дефект брифа НЕ закрыт как класс

Самое важное здесь. Миссия пакета — «русской клинике показывается сырой английский токен». После
правки `crownType` вычищен, а **`brand` льёт ровно тот же токен в ту же строку**. Замерено
исполнением `pricelistItemMaterialText` на HEAD:

```
brand="unknown"      -> «Материал по разбору: unknown · Цирконий · Коронка»
brand="N/A"          -> «Материал по разбору: N/A · Цирконий · Коронка»
brand="unspecified"  -> «Материал по разбору: unspecified · Цирконий · Коронка»
brand="unknown", остальное unknown -> «Материал по разбору: unknown»
```

Последняя строка — буква в букву дефект, из-за которого пакет заведён.

Это не гипотеза, модель прямо к этому побуждается. Механизм симметричен crownType:

- `packages/shared/src/index.ts:1747` — `brand: z.string().nullable()`, свободная строка, не enum;
- `apps/api/src/pricelist/analyzer.ts:1552` — `brand: record.brand === null ? null : asString(record.brand, fallback.brand ?? "") || null`, то есть passthrough, `|| null` обнуляет только пустую (строка 1551 для `crownType` — та же самая);
- `apps/api/src/pricelist/analyzer.ts:1378` — **строка промпта, которую он редактировал, до сих пор гласит**: `"If a price is absent, use null. If a material/brand/crown type is uncertain, use unknown or null."`

Он добавил на 1386 override для `crownType` («never the word unknown and never free text») и оставил
половину той же фразы про **brand** нетронутой. В промпте теперь противоречие: одна строка запрещает
слово `unknown` для crownType, другая разрешает его для brand. `brand` при этом печатается ПЕРВЫМ
в списке меток и никогда не отбрасывается дедупликацией (индекс 0 — сравнивать не с чем).

Оговорка в его пользу: brand — имя собственное, его не переводят, и карты для него нет by design, так
что «резервная ветка» здесь не годится — лечить надо на входе (промпт + отбрасывание служебных
заглушек `unknown`/`n/a`/`none` в `brand`). Поле в брифе не названо, поэтому это FOUND для следующего
пакета, а не невыполненная работа OO2. Но класс дефекта пакет не закрыл, и заявлять его закрытым
нельзя.

### 2. Дедупликация односторонняя, и его собственное правило шире его кода. Заикание осталось на реальной строке прайса

Коммит `4607ca9fc` заявляет правило: «метка не печатается, если она ЦЕЛИКОМ содержится в одной из уже
оставленных». Код реализует лишь подмножество — отбрасывается только метка, содержащаяся в
**РАНЕЕ** оставленной (`kept.some((existing) => existing.toLowerCase().includes(normalized))`).
Обратное направление (общая метка раньше, уточняющая позже) не покрыто.

Измерено сквозным прогоном настоящего `analyzePricelist` (детерминированный режим, `useServerAi:false`)
с подачей результата в `pricelistItemMaterialText`:

```
"Коронка на импланте титановая 45000"
  crownType="crown" materialKind=implant_system restorationType=implant_crown
  SCREEN: «Материал по разбору: Коронка · Имплант-система · Коронка на импланте»

"Коронка на импланте 45000"
  SCREEN: «Материал по разбору: Коронка · Имплант-система · Коронка на импланте»
```

«Коронка» буквально содержится в «Коронка на импланте» — то есть по его сформулированному правилу
печататься не должна, а печатается, потому что пришла раньше. Это обычная строка любого
ортопедического прайса, не нейро-путь. В остатке долга он объявил ТОЛЬКО случай PMMA (пересечение по
смыслу, не по буквам), из чего читатель заключит, что буквальное вхождение закрыто полностью. Не закрыто.

Дешёвое лечение: после сбора списка отбрасывать метку, если она содержится в ЛЮБОЙ другой оставленной,
а не только в предшествующей (порядок «от точного к общему» тогда решает, кто выживет).

- **Сквозной путь Groq не исполнялся** — ни им, ни мной: ключа нет, платный вызов запрещён. Правка

  доказано быть здесь не может; защита экрана стоит на стороне интерфейса и от послушания модели не

- **`npm run smoke:pricelist-analyzer` остаётся красным** по предсуществующей несвежести `dist`.
  Снимается `npm run build -w @dental/api` — общий гейт, мной не запускался по условию ревью.
- **Общие гейты не запускал** по условию: полный `npm run typecheck`, `npm run build`, весь `npm test`,
  миграции, сиды.
- `crownType` в контракте остался `z.string().nullable()`. Его отказ делать enum обоснован верно:
  enum на этом поле уронил бы валидацией ВЕСЬ разбор прайса из-за одной свободной подписи. Но
  наблюдение верное — любой новый потребитель `crownType` наследует ту же ловушку. Правильный ход не
  enum, а нормализация на входе API; это не работа OO2.

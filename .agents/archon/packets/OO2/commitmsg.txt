[ARCHON] fix(прайс): русской клинике печатался английский токен «unknown» — тип коронки с нейро-пути выводился как есть

`pricelistCrownTypeLabel` заканчивался `pricelistCrownTypeLabels[value] ?? value`, то есть значение, которого
в карте нет, уходило на экран без перевода. Измерено исполнением функции на HEAD до этой правки (не чтением):

    crownType "unknown"                -> «Материал по разбору: unknown»
    crownType "zirconia crown"         -> «Материал по разбору: zirconia crown»
    "full ceramic" + ceramic + crown   -> «Материал по разбору: full ceramic · Керамика · Коронка»
    crownType "Zirconia"               -> «Материал по разбору: Zirconia»
    crownType "zirconia_multilayer"    -> «Материал по разбору: zirconia_multilayer»

Почему это законный вход, а не редкий сбой: `crownType` объявлен в контракте `z.string().nullable()`
(`packages/shared/src/index.ts:1746`), НЕ перечислением, а системный промпт Groq перечисляет допустимые
значения для `category`, `specialty`, `materialKind`, `restorationType` и НЕ перечисляет их для `crownType`,
при этом прямо разрешая «If a material/brand/crown type is uncertain, use unknown or null». Разбор ответа
пропускает строку как есть (`asString`, `|| null` обнуляет только пустую). Детерминированный
`detectCrownType` (`apps/api/src/pricelist/analyzer.ts:320-329`) отдаёт ровно 7 значений и все 7 в карте
есть — утечка была только на нейро-пути, но он продуктовый.

Ключ теперь нормализуется (регистр, подчёркивания, дефисы, двойные пробелы) и ищется в карте вместе со
списком англоязычных синонимов тех же семи значений, а всё НЕ ОПОЗНАННОЕ считается ОТСУТСТВИЕМ ДАННЫХ:
возвращается null, метка не печатается. Побочно закрыт дефект, замеченный ревьюером волны NN: фраза
«материал не распознан» была НЕДОСТИЖИМА при ответе модели «всё unknown», потому что метка коронки всегда
оказывалась непустой.

Почему не заглушка «Коронка, материал уточнить»: это текст, которого модель не сказала. Отсутствие данных
обязано выглядеть как отсутствие — та же причина, по которой `?? 0` нельзя печатать вместо неизвестной суммы.
Почему синонимы списком, а не поиском подстроки: подстрока молча превратила бы «non-zirconia» и любую
будущую формулировку модели в утверждение о материале, которого модель не сказала.

Проверка `apps/web/src/tests/pricelistUiMeta.test.ts` краснеет от возврата ровно этого дефекта, а не от
поломки синтаксиса. Мутирована КОПИЯ в /tmp (`return pricelistCrownTypeNormalizedLabels.get(normalized) ??
null` -> `return pricelistCrownTypeLabels[value] ?? value`), исходники в дереве не тронуты:

    cd apps/web && node --import tsx --test src/tests/pricelistUiMeta.test.ts   -> 0, 28/28 pass
    cd apps/web && node --import tsx --test /tmp/oo2/pricelistUiMeta.test.ts    -> 1, 21/28 fail

Семь проходящих на мутанте — детерминированные значения, они и обязаны проходить: это защита от
пере-починки, чтобы «неопознанное -> null» не съело работающие подписи.

[ARCHON] docs(снимки): сдача по утечке образца DICOM между арендаторами

Доказательная часть пакета R4 отдельным коммитом, чтобы код лежал в истории
раньше отчёта о нём.

Что зафиксировано:
- Отрицательный контроль. Те же 17 тестов на пре-фиксном маршруте: 12 проходят,
  5 падают, главный — с «200 !== 404». Без этого прогона новые тесты были бы
  декоративными: непонятно, ловят они дефект или просто описывают текущее
  поведение. Пре-фиксный файл был положен в дерево через git show, прогон, затем
  git checkout -- для восстановления; в индекс ничего не попадало.
- Живые пробы на 127.0.0.1:4100. Проба G ревьюера (токен второй организации)
  давала 200 application/dicom и 121356 байт — стало 404. Проба H (организация,
  которой нет ни в одной строке organizations) давала те же байты — стало 403
  OrganizationUnknown. Выдуманные UID остались 404, то есть проверка
  идентичности из пакета C1 не сломана.
- Цепочка владения этим доказательством. Процесс на 4100 запущен без --watch и
  не мной. Что он исполняет мой код, установлено по поведению, а не по времени
  запуска: кода ошибки OrganizationUnknown в пре-фиксном коммите нет вовсе.
- Чего не доказано и какой командой это закрывается: живая выдача 200
  организации-владельцу (на сервере не задан DENTE_DICOM_SAMPLE_ORGANIZATION_ID,
  подстановка переменной в запущенный процесс невозможна, перезапуск шарового
  сервера — право ведущего) и живой 403 гейта клинического чтения (в apps/api/.env
  послабление включено при пустом секрете).
- Поправка к клейму пакета: файла apps/api/src/tests/**/dicomweb.test.ts не
  существует, тесты dicomweb лежат рядом с маршрутом.
- Следующий пакет назван прямо: requireOrganizationId (security/identity.ts)
  отдаёт организацию из подписи, не проверяя её существование, и это свойство
  общего гейта для всех маршрутов, а не только этого.

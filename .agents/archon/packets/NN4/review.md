## Бриф был неверен, и исполнитель прав — проверено, а не принято на слово

Диагноз брифа «путь собран сложением строк вместо `path.join`» опровергается. Я воспроизвёл механизм
напрямую:

```
$ printf '%b\n' 'C:\\Clinic_MVP\\dental-crm\\apps\\web\\src' | cat -v
C:\Clinic_MVP\dental-crm^Gpps\web\src
```

`\a` разворачивается в BEL (`^G`), буква «a» у «apps» съедается — получается ровно «dental-crmpps\web»
из брифа. Конкатенации пути в обоих стражах нет: `rg -n 'path\.|readFileSync\([^"]'` по двум файлам
даёт единственное попадание — новый `` `${MIGRATIONS_DIR}/${name}` `` для обхода каталога миграций.
Подгонка константы пути действительно ничего бы не дала. Второе возражение исполнителя («остальные
четыре печатают внятные списки причин») тоже верно — все четыре печатают именованные списки.

Системный дефект переводов строк подтверждён своим замером: `core.autocrlf=true`,
`main.css` 17375 CRLF / 0 одиночных LF, `sampleData.ts` 12738 CRLF / 0 LF, `App.tsx` 0 CRLF / 5073 LF.
Требование с литералом `\n` в таком дереве — монетка. (У исполнителя для `sampleData.ts` стоит 12657
против моих 12738 — расхождение метода счёта, на вывод не влияет.)

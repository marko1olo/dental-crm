## Что изменено

`apps/api/src/routes/dicomweb.ts` переписан целиком (32 -> 285 строк).
`apps/api/src/routes/dicomweb.test.ts` расширен с 1 до 9 проверок.

Порядок разрешения UID, всё в пределах организации из подписанного токена:

1. `imaging_instances -> imaging_series -> imaging_studies` внутренним
   соединением. Совпасть должны все три UID сразу, `organization_id`
   проверяется на каждом из трёх уровней соединения (одной строки с неверной
   ссылкой достаточно, чтобы снимок ушёл в другую клинику). База здесь —
   индекс истины, повторно разбирать байты незачем. Единственный путь,
   пригодный для многокадровых томов.
2. `imaging_studies.storage_path`. Строка подтверждает только UID
   исследования, поэтому серию и объект обязаны подтвердить сами байты файла:
   читается ограниченный префикс (1 МиБ), разбор dicom-parser
   останавливается на теге 0020,000E, сравниваются 0020,000D / 0020,000E /
   0008,0018. Иначе тот же обман вернулся бы уровнем выше — один файл на любую
   серию внутри исследования.
3. Демонстрационный файл — только под теми UID, которые физически записаны в
   нём самом. Списка разрешённых UID в коде нет: тождество берётся из файла.

Ни один источник не подтвердил — 404 `DicomInstanceNotFound`. Тело ответа
одинаково для чужого UID и для несуществующего, чтобы перебором нельзя было
выяснить состав архива соседней клиники. Отдельный код
`DicomInstanceFileUnreadable` (404), когда файл числится, но не читается с
диска, и `DicomInstanceUidMissing` (400) на пустой UID в адресе.

Путь к образцу вынесен в `DENTE_DICOM_SAMPLE_PATH`; прежнее размещение
осталось значением по умолчанию.

Дескриптор файла в `readDicomIdentity` закрывается в `finally` при любом
исходе разбора — маршрут вызывается на каждый кадр.

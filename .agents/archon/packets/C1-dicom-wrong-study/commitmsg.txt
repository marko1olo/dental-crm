[ARCHON] fix(снимки): любой UID отдавал один и тот же DICOM-файл

GET /api/dicomweb/studies/:studyUid/series/:seriesUid/instances/:instanceUid
разбирал все три идентификатора и не использовал ни одного. Существующий UID,
чужой UID, выдуманный UID — ответ был один: 200, application/dicom и байты
.data/dicom/test.dcm. Просмотрщик получал корректный DICOM на любой запрос и
не имел никакой возможности отличить настоящее исследование от заглушки. Для
стоматологии это значит удаление или имплантацию, спланированные по анатомии
другого человека.

Вторая половина того же дефекта: маршрут не проверял ни авторизацию, ни
организацию. Снимки — медицинские данные — отдавались без токена, и соседняя
клиника в той же установке получала их наравне с владельцем.

Теперь UID обязан разрешиться в конкретный файл в пределах организации из
подписанного токена:
- imaging_instances -> imaging_series -> imaging_studies, совпадение всех трёх
  UID сразу, organization_id проверяется на каждом уровне соединения;
- imaging_studies.storage_path (то, что заполняет POST /api/imaging/studies)
  подтверждает только UID исследования, поэтому серию и объект подтверждают
  сами байты файла — иначе один файл снова отвечал бы на любую серию;
- демонстрационный файл отдаётся исключительно под теми UID, которые
  физически записаны в нём самом; списка разрешённых UID в коде нет.
Не подтверждено ничем — 404 с машиночитаемым кодом, одинаковый для чужого и
для несуществующего UID, чтобы перебором нельзя было выяснить состав архива
соседней клиники.

Путь к демонстрационному файлу вынесен в DENTE_DICOM_SAMPLE_PATH, прежнее
размещение осталось значением по умолчанию.

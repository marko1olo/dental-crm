[ARCHON] test(состояние): число записей снимка на пачку действий никто не измерял

Тестов на persistMutableState() не было вообще: persistentState.test.ts
проверяет запись, чтение и контрольную сумму одного вызова
savePersistentState(), но ни один тест не считал, сколько раз файл состояния
переписывается на N действий пользователя. Именно это и было дефектом.

Тест считает реальные записи файла (перехват fs.writeFileSync по точному пути
временного файла, с проходом в настоящую запись) и фиксирует:
  • синхронный режим DENTAL_STATE_FLUSH_DELAY_MS=0 — прежнее поведение:
    20 действий -> 20 записей, 725 680 Б;
  • окно 60 мс — 20 действий -> 1 запись, 36 284 Б, причём ноль записей в
    такте самого действия, то есть запись ушла с пути запроса;
  • поток из 25 действий по одному каждые 10 мс -> 7 записей, а не 25:
    окно фиксированное, поэтому запись не откладывается бесконечно
    (продлеваемое окно не записало бы файл ни разу до конца потока);
  • в файл попадает последнее значение пачки, а не первое;
  • нечитаемое значение переменной окружения даёт окно по умолчанию, а не
    тихий возврат к записи на каждое действие.

Первое утверждение обязательно: если счётчик записей перестанет работать,
тест упадёт на нём, а не сделает вид, что слияние доказано.

DENTAL_STATE_FILE и DENTAL_STATE_BACKUP_DIR уводятся в os.tmpdir() ДО импорта
sampleData.ts, поэтому рабочий apps/api/.data/dental-crm-state.json тест не
читает и не пишет.

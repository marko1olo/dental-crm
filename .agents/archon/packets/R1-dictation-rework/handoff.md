## Что изменено

Один файл продукта — `apps/api/src/speech/storage.ts`. Тесты: `src/speech/tests/storage.test.ts`
(+5 проверок) и новый `src/speech/tests/storageRestoreRetry.test.ts` (3 проверки).
`db/schema.ts` НЕ тронут, миграций нет, веб не тронут, сигнатуры экспортов сохранены
(`routes/speech.ts` и `speech/gateway.ts` не менялись).

1. **Запись сливается с сохранённым конвертом, а не переписывает его.**
   `loadDurableRecordingEnvelope()` читает строку по `(organization_id, input_storage_path)` ВНУТРИ
   той же очереди записи по `recordingId`, `mergeDurableAndCachedChunks()` объединяет фрагменты по
   номеру. Кто из двух версий одного номера лучше, решает тот же `shouldReplaceSpeechTranscriptionChunk`,
   по которому повторное распознавание заменяет фрагмент в памяти. Из конверта и текста больше ничего
   не теряется, даже когда кэш вытеснен до одного фрагмента.
2. **Нечитаемое не уничтожается.** Записи конверта, не прошедшие `speechTranscriptionChunkSchema`,
   переносятся в новый конверт байт-в-байт в поле `unreadableChunks`, и в строку добавляется
   предупреждение с их числом. Совсем нечитаемый конверт (не JSON, нет массива) отменяет запись
   через `SpeechDurableEnvelopeUnreadableError`: строка в базе остаётся нетронутой, фрагмент
   остаётся в памяти с предупреждением. Правило простое — не перезаписывай то, что не смог прочесть.
3. **Префикс `speech-recording://` ушёл в WHERE**, а восстановление стало per-tenant:
   `row_number() OVER (PARTITION BY organization_id ORDER BY updated_at DESC)` с лимитом на клинику.
   Один запрос, параметры `['voice_transcription', 'speech-recording://%', 80]`.
   Нечитаемый конверт одной строки больше не роняет весь проход: строка пропускается, счётчик уходит
   в предупреждение врачу.
4. **Вытеснение считает бюджет по организации** (`trimSpeechTranscriptionChunkRetention`), поэтому
   поток диктовок одной клиники не выбивает запись другой.
5. **Восстановление повторяется.** После провала `speechRestorePromise` сбрасывается в `null`,
   следующая запись пробует снова, но не раньше выдержки `DENTAL_SPEECH_RESTORE_RETRY_MS`
   (по умолчанию 5000 мс, удваивается до седьмой попытки). Причина, число неудачных попыток и время
   следующей доступны через `speechDurableRestoreState()` и попадают в предупреждение сборки записи.
6. **`confidence` пишется явно на обоих путях** (`confidence ?? unknownConfidenceColumnValue`), а
   неизвестность объявляется в `warnings` той же строки: «Уверенность распознавания не сообщена ни
   одним фрагментом: ноль в поле confidence означает отсутствие оценки, а не нулевую уверенность.»
   Если оценка есть не у всех фрагментов, в строку пишется покрытие («известна только для N из M»),
   а не молчаливое среднее по подмножеству. Тот же UI, что печатает процент, печатает и `warnings`.
7. **`target` выводится из источника** (`visit` → `visit_note`, `import` → `patient_import`,
   `document`/`settings_lab` → `document_draft`) вместо жёсткого `visit_note` для всего.
8. **Предупреждение «Фрагмент не сохранен в базу» больше не становится долговременным**: оно
   вырезается из конверта и снимается с кэша после удавшейся записи. В само предупреждение добавлено
   число несохранённых фрагментов в памяти — цена запрета на уничтожение текста должна быть видна.

## НЕ ПРОВЕРЕНО

- **UI не проверял** — это право ведущего, я его не заявляю.
- **Гонка двух процессов API на одной строке `ai_jobs`.** Слияние читает и пишет внутри
  внутрипроцессной очереди по `recordingId`; на `(organization_id, input_storage_path)` уникального
  индекса нет (в `pg_indexes` у `ai_jobs` только `ai_jobs_pkey`), поэтому два процесса могут
  прочитать один конверт и записать по очереди, потеряв фрагменты второго.
  Закрывается: миграция с `unique (organization_id, input_storage_path)` на `ai_jobs`, затем
  `cd apps/api && npm run db:migrate && node --import tsx --test src/speech/tests/storage.test.ts`
  плюс новая проверка на два процесса. Миграция вне делянки — решение ведущего.
- **Сколько именно несохранённых фрагментов выдержит процесс.** Что фрагмент не выбрасывается и
  несёт предупреждение — проверено; предела памяти я не измерял.
  Закрывается: `cd apps/api && node --import tsx --input-type=module -e "<цикл на 10000 фрагментов с
  несуществующим visitId>; console.log(process.memoryUsage().heapUsed)"` и сравнение с
  `--max-old-space-size`.
- **Полная недоступность PostgreSQL на живом сервере.** Проверено закрытием пула в отдельном
  процессе; службу `postgresql-x64-18` я не останавливал — она общая для двух других агентов фленты
  и dev-сервера.
  Закрывается (в одиночном окружении): `net stop postgresql-x64-18`, затем
  `curl -s -X POST http://127.0.0.1:4100/api/speech/transcribe-chunk ...` и проверка предупреждения
  «Фрагмент не сохранен в базу», затем `net start postgresql-x64-18`.
- **Восстановление после настоящего перезапуска процесса.** Тест проходит границу через
  `resetSpeechTranscriptionCacheForRestart()` плюс чтение из базы, а не через убийство процесса.
  Закрывается: `touch apps/api/src/speech/storage.ts` (рестарт tsx watch — теперь подтверждено, что
  watch работает), затем
  `curl -s -H "x-dente-clinic-token: <token>" "http://127.0.0.1:4100/api/speech/chunks?recordingId=<id>&visitId=<visitId>"`.

## Долг

1. **Уникальный индекс `ai_jobs (organization_id, input_storage_path)`** — закрывает гонку двух
   процессов и коллизию ключей вида `"short_" + Date.now()` из веба. Требует миграции.
2. **`ai_jobs.confidence` не умеет хранить «неизвестно»** (`real NOT NULL DEFAULT 0`). Нужна
   миграция на nullable плюс `AiRecognitionJob.confidence: number | null` в `packages/shared` плюс
   правка `db/aiQuery.ts` (`?? 0`) и `SettingsAiTab.tsx:311`. Пока неизвестность объявлена только
   предупреждением в той же строке.
3. **Межарендная дыра на чтении диктовки** — `routes/speech.ts:107-147 validateSpeechClinicalScope()`
   ищет пациента и прием только по id, без организации из токена. Токен клиники A получает фрагменты
   клиники B. Пре-существующая, объявлена ещё в C4, отдельный пакет.
4. **Вытесненные фрагменты не отдаются на чтение** до восстановления кэша, хотя лежат в `ai_jobs`:
   `listSpeechTranscriptionChunks`/`assembleSpeechRecording` синхронны, ленивая подгрузка требует
   асинхронности в `routes/speech.ts`. Потери текста больше нет — есть невидимость.
5. **`visits.transcript` по-прежнему пуст**: собранный текст лежит в `ai_jobs`, а не в колонке приема
   (`db/schema.ts:351`). Отдельный пакет.
6. **Три копии хранилища диктовки в памяти** — живая `speech/storage.ts` и мёртвые
   `sampleData.ts:1247`, `sampleData_opt.ts:1047`, протянутые в `persistentState.ts:52`. Пре-существующее.
7. **i18n**: серверные предупреждения диктовки — русские строки в коде, словаря для них нет. Я добавил
   к этому долгу, а не уменьшил его.
8. **`npm run smoke:speech-clinical-scope` красный** из-за расхождения текста `dentalPrompt.ts` с

## Зелёный тест, не проверяющий ничего — НЕТ. Мутация прогнана, не рассуждение

Правку отменил обратимо (файл был чист по HEAD; вставил строку долга назад, прогнал, восстановил

`MUTATED_EXIT=1`, `fail 2`, и краснеют ровно те две проверки, которые правка касается:

- `починенные адреса удаляются из списка долга` — `AssertionError: Эти пары уже обслуживаются — маршрут
  добавлен, уберите строку из KNOWN_METHOD_MISMATCH: DELETE /api/clinical/rules/:param`;
- `список известного долга не разрастается молча` — `AssertionError: Известных расхождений по методу стало
  больше: 2` — то есть сверхбрифовое опускание потолка `<= 2` → `<= 1` тоже НЕ украшение, оно бьёт.

Восстановление с первого раза не удалось: `.git/index.lock` держал параллельный процесс волны. Файл
восстановлен ретраем, `git status --porcelain` по нему пуст, `git diff HEAD` по нему пуст.

Снятие строки не ослабляет, а УСИЛИВАЕТ охрану, и это тоже замер, а не довод. В мутированном прогоне
проверка `в списке долга нет адресов, которых никто не зовёт` осталась зелёной с восстановленной строкой →
`webCallsWithMethod()` действительно находит пару `DELETE /api/clinical/rules/:param`
(`apps/web/src/useAppLogic.tsx:11066`, `removeClinicalRule`, `method: "DELETE"`). А в чистом состоянии
зелена `каждый вызванный адрес обслуживается ТЕМ ЖЕ методом` → значит `isServed(candidate, withMethod)`
истинно, то есть `withMethod` содержит эту пару. Следствие: уберите `app.delete` из clinical.ts — и страж
покраснеет на живом вызове. Раньше эта пара была ЗАГЛУШЕНА списком долга и регресс прошёл бы молча.

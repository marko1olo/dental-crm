[ARCHON] fix(расписание): панель логов внешних ботов не могла получить данные ни при каком действии

Удалён apps/web/src/components/schedule/ExternalScheduleActionLogsWidget.tsx и его монтирование
в ScheduleView.tsx. Это не уборка по вкусу: пользователь на экране расписания видел карточку с
заголовком «Лог внешних сервисов записи (Забота 2.0 / LoyalMed AI Боты)» и значком «Внешние боты
записи», которая не могла наполниться никогда.

ПРОВЕРЕНО РУКАМИ, ТРИ НЕЗАВИСИМЫХ ФАКТА:

1. Виджет запрашивал /api/schedule/external-schedule-action-logs (строка 28). Такого маршрута в
   API нет. Живой сервер отвечает 404 — проверено запросом к 127.0.0.1:4100. Единственное
   вхождение этого адреса во всём apps/api — список известных отсутствующих в охранном тесте
   webCallsExistingRoutes.test.ts:67.

2. Даже если маршрут написать, наполнять его нечем: таблица external_schedule_action_logs
   объявлена в schema.ts:1858, но во всём репозитории у неё НОЛЬ писателей — ни drizzle-вставки,
   ни сырого INSERT.

3. Интеграции с внешними сервисами записи, которая эти логи производила бы, в проекте нет.
   Выдумывать её контракт запрещено: чего нет — то долг с причиной, а не фантазия.

Поведение, которое видел пользователь: запрос падал в 404, res.json() на теле ошибки не давал
массива, setLogs([]) — и карточка молча показывала пустое состояние под уверенным заголовком.
Это не недостающая функция, а интерфейс без функции.

ПОЧЕМУ УДАЛЕНИЕ, А НЕ РЕАЛИЗАЦИЯ. Реализовать маршрут означало бы отгрузить панель, которая
останется пустой навсегда, потому что писателя нет и взяться ему неоткуда. Панель, которая не
может наполниться, хуже отсутствующей функции: она обещает то, чего не будет.

ЧЕГО НЕ СДЕЛАЛ И ПОЧЕМУ. Адрес остаётся в KNOWN_MISSING в
apps/api/src/tests/webCallsExistingRoutes.test.ts — запись стала ненужной, но файл в этот момент
правит другой автор, и по правилу командной работы чужие несохранённые правки не трогаются.
Записано долгом. Тест от удаления не падает: я прочитал его логику — строка 237 пропускает
адреса из списка, строка 266 требует, чтобы список не РОС, строки 274-278 требуют, чтобы адрес из
списка не обслуживался. Утверждения «адрес обязан по-прежнему вызываться вебом» там нет.

Таблицу external_schedule_action_logs не удалял: это миграция, то есть общий гейт, и её судьбу
решает отдельный пакет. Она безвредна, просто не используется.

ПРОВЕРЕНО: npm run typecheck -w @dental/web — 0 ошибок, прогнан мной последовательно (§7a).
Проверка висячих ссылок по ВСЕМУ репозиторию: живых вхождений имени нет, осталась только
поясняющая проза в комментарии на месте удалённого монтирования.

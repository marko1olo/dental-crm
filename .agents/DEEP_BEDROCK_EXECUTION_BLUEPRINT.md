## 3. ПОЛНЫЕ БОЕВЫЕ ТЗ ДЛЯ ТЯЖЕЛОГО МОЗГА (NEON 4)

### ТЗ CORE-1: Fastify Universal Mutation Shield & RFC 9562 Idempotency
- **Целевые файлы:** `apps/api/src/plugins/idempotencyPlugin.ts`, `apps/api/src/serverModules/lifecycleHooks.ts`, `apps/api/src/routes/`.
- **Проблема сейчас:** В `idempotencyPlugin.ts` зашит хрупкий список регулярных выражений `enforceForPaths`. Если роут туда не попал (а их больше 20 штук по результатам `audit:dice`), запрос не защищен от дублей. Роуты мутаций принимают мутации мимо `organizationId`.
- **Архитектурное решение:**
  1. Инвертировать логику `isEnforced`: по умолчанию **ВСЕ HTTP-методы `POST`, `PUT`, `PATCH`, `DELETE` подлежат обязательной проверке `Idempotency-Key` (UUIDv7)**.
  2. Создать явный минимальный белый список исключений (`exemptPaths`): `/api/auth/login`, `/api/auth/refresh`, `/api/health`, `/api/ping`, `/api/telephony/webhook`, `/api/whatsapp/webhook`.
  3. Для всех остальных маршрутов отсутствие валидного ключа возвращает `400 Bad Request` с кодом `IdempotencyKeyRequired`.
  4. Обеспечить, чтобы в контексте мутации `organizationId` проверялся строго до обращения к данным сущности (защита от IDOR). Если сущность не принадлежит тенанту — немедленный `404 Not Found` (не паля существование записи).
- **Машинный гейт:** Запуск `npm run audit:dice`: 0 дефектов по разделу «Fastify Mutation Route Gateway».

### ТЗ CORE-2: Математический калькулятор сплит-чеков 54-ФЗ (Hamilton SSOT)
- **Целевые файлы:** `packages/shared/src/billing/splitPaymentAllocator.ts`, `apps/api/src/routes/cashbox/paymentStages/splitAllocationStage.ts`, `packages/shared/src/billing/__tests__/splitAllocationMath.test.ts`.
- **Проблема сейчас:** При распределении скидок клиники (до 100% по Мандату 8e) и сплит-платежей (нал + эквайринг + семейный депозит + бонусы) наивные деления и `Math.round()` теряют 1–2 копейки. Фискальный регистратор блокирует чек.
- **Архитектурное решение:**
  1. Реализовать чистую функцию `allocateSplitPaymentAcrossItems()` на целых копейках (`BigInt` / целочисленный `number`).
  2. Использовать метод наибольшего остатка (Largest Remainder Method / алгоритм Гамильтона):
     $$\text{share}_i = \frac{\text{itemPrice}_i \times \text{paymentAmount}}{\text{totalBill}}$$
     Целая часть копеек начисляется сразу: $\text{allocated}_i = \lfloor \text{share}_i \rfloor$.
     Остаток копеек $R = \text{paymentAmount} - \sum \text{allocated}_i$ по 1 копейке распределяется по позициям с наибольшей дробной частью $(\text{share}_i - \lfloor \text{share}_i \rfloor)$.
  3. Если скидка на позицию составляет 100% (анестезия в подарок), позиция фискализируется с ценой 0 копеек и признаком расчета «безвозмездно/скидка», не нарушая баланс чека.
- **Машинный гейт:** Property-based тест (fast-check) на 20 000 случайных комбинаций сумм и скидок: $\sum \text{allocatedLines} \equiv \text{paymentAmount}$ с точностью строго до 0 копеек.

### ТЗ CORE-3: Анатомический движок Wheeler 2.5D MODBL
- **Целевые файлы:** `packages/shared/src/clinical/odontogram/`, `apps/web/src/components/odontogram/gate0/teeth/`, `apps/api/src/routes/odontogram/`.
- **Проблема сейчас:** Статус зуба хранится монолитно. Кариес на окклюзионной грани (O) затирает ранее установленную пломбу на медиальной грани (M).
- **Архитектурное решение:**
  1. Разбить анатомию коронки на 5 независимых поверхностей: `Mesial (M)`, `Occlusal (O)`, `Distal (D)`, `Buccal (B)`, `Lingual (L)` + пришеечная зона (`Cervical`) и корни (`Roots`).
  2. Хранить состояние зуба как объект поверхностей:
     ```typescript
     export interface ToothSurfaceState {
       readonly status: ToothSurfaceCondition; // "intact" | "caries" | "restoration" | "sealant"
       readonly material?: RestorationMaterial; // "composite" | "ceramic" | "amalgam"
       readonly dateApplied?: string;
     }
     ```
  3. SVG-рендерер изолирует полигоны каждой грани: клик по полигону O меняет статус только O-поверхности, не трогая M и D.
  4. Формирование МКБ-10: если поражены 2+ грани (например, M + O), система автоматически выводит диагноз `K02.1` с расширением `MOD`.
- **Машинный гейт:** Юнит-тест: нанесение кариеса на O-грань зуба 46 оставляет M-грань в статусе `restoration (composite)`.

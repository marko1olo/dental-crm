## 1. АППАРАТНЫЕ И ПРОГРАММНЫЕ ИНВАРИАНТЫ

### 1.1. Прямая TData-авторизация (без SMS и внешних API ID)
- Для подключения используется локальная сессия активного Telegram Desktop:
  * Путь: `C:\Users\Admin\AppData\Roaming\Telegram Desktop\tdata`
  * Библиотеки: `tgconvertor[tdata]` + `opentele2` + `telethon` (совместимо с Python 3.13+).
  * Аккаунт: `account_index=0` (`@matveyihinib`, ID: `1890028643`).
- **Код инициализации клиента:**
  ```python
  from TGConvertor import SessionManager
  
  TDATA_PATH = r"C:\Users\Admin\AppData\Roaming\Telegram Desktop\tdata"
  mgr = SessionManager.from_tdata_folder(TDATA_PATH, account_index=0)
  client = mgr.telethon_client()
  await client.connect()
  ```

## 2. ПРОТОКОЛ ВЗАИМОДЕЙСТВИЯ С БОТОМ (@sydney_ai_bot)

### 2.1. Инвариант стейт-машины inline-кнопок (MessageEdit)
Бот **НЕ отправляет новые сообщения** при кликах по inline-кнопкам настроек — он **редактирует то же самое сообщение** (`MessageEdited` / изменение структуры на месте).
- Попытка искать новое сообщение через `msg.id > last_id` приводит к зависанию!
- **Канонический алгоритм переключения модели:**
  1. Отправить `/settings` ➔ дождаться нового сообщения с кнопками (`settings_msg_id`).
  2. Нажать кнопку текущей модели `[0,0]` (`🤖 Model Name...`).
  3. Получить обновленное сообщение по ID: `msgs = await client.get_messages(bot, ids=[settings_msg_id])`.
  4. В обновленном сообщении найти кнопку провайдера (`Google`, `OpenAI`, `Anthropic`, `Deepseek`, `Grok`, `Moonshot`, `Alibaba`, `Zhipu`) и нажать её.
  5. Снова получить обновленное сообщение по тому же `settings_msg_id`.
  6. Нажать кнопку нужной модели.
  7. Отправить `/newchat` для сброса контекста сессии перед новым диалогом.

### 2.2. Защита от перехвата собственного промпта
При ожидании ответа бота через `get_messages` обязателен жесткий фильтр отправителя:
```python
# КРИТИЧЕСКИЙ ФИЛЬТР: игнорируем свои исходящие сообщения!
new_replies = [
    m for m in messages 
    if m.id > after_id and not m.out and m.sender_id == bot_entity.id
]
```
Без `not m.out` скрипт перехватит собственный отправленный промпт как «ответ»!

### 2.3. Парсинг Instant View (Rich Messages)
Бот возвращает развернутые ответы через Telegram Instant View (`cached_page` / `PageBlockDetails` / `PageBlockParagraph`), а не через обычное поле `msg.text`.
- Для извлечения полного Markdown-текста с сохранением блоков мыслей (`<details>`) и таблиц используется утилита:
  `C:\Clinic_MVP\dental-crm\scratch\sydney_userbot\rich_extractor.py` (`extract_rich_text(msg)`).

## 4. КАТАЛОГ ФОНОВЫХ ДЕМОНОВ КЛИНИКИ

### Демон 1: Еженедельный стратегический дайджест клиники (Weekly Executive Digest)
- **Целевая модель:** `Claude Opus 5.5` или `Claude Fable 5.2`.
- **Триггер:** Cron-задача Fastify / Windows Task Scheduler каждое воскресенье в 02:00.
- **Входные данные:** Анонимизированный JSON из PostgreSQL:
  * Выручка по врачам, креслам и направлениям (терапия, ортопедия, хирургия).
  * Воронка планов лечения: процент принятых смет vs отказных.
  * Критические остатки расходников и списания (Soft Negative Stock).
  * Рекламации и гарантийные перелечивания.
- **Результат:** PDF / Telegram-сводка главврачу и владельцу с анализом узких мест и рекомендациями по загрузке кабинетов.

### Демон 2: Ночной аудит медкарт и протоколов (Nightly SOAP QA Auditor)
- **Целевая модель:** `Gemini 4 Argon` или `DeepSeek V4.1 Flash`.
- **Триггер:** Ежедневно в 03:00.
- **Входные данные:** Все амбулаторные карты и дневники SOAP (`visitNoteDraft`), оформленные за прошедший рабочий день.
- **Проверка:**
  * Соответствие диагноза МКБ-10 описанному лечению (стандарты СтАР).
  * Наличие обязательных полей (анестезия, коффердам, протокол ирригации).
  * Выявление юридических рисков до проверки страховых компаний (ОМС/ДМС).

### Демон 3: Междисциплинарный клинический консилиум (Multi-Model Consilium)
- **Целевая модель:** Параллельный опрос `Claude Sonnet 5.5` + `GPT-6 Sol`.
- **Триггер:** По нажатию кнопки врача «Запросить консилиум» в карточке пациента со сложным диагнозом (пародонтит + диабет + необходимость тотальной реабилитации).
- **Результат:** Сводная матрица альтернативных протоколов и рисков к следующему визиту пациента.

## 2. Logic Chain

1. **Frontend Construction**:
   In `useVisitLogic.ts:1399-1400`, the frontend explicitly sends `planPayload: null` and `recommendationsPayload: null` when requesting `/api/ai/visit-flow`.
2. **Schema Inconsistency**:
   In `packages/shared/src/index.ts:11269-11270`, `visitFlowRequestSchema` defines:
   - `planPayload: treatmentPlanPayloadSchema.optional()`
   - `recommendationsPayload: postVisitRecommendationsPayloadSchema.optional()`
   In Zod, `z.optional()` expects `undefined` or a valid object, but **rejects `null`** with `invalid_type` (`Expected object, received null`).
3. **Validation Breakdown**:
   When the server handles `POST /api/ai/visit-flow`, `visitFlowRequestSchema.safeParse(request.body)` fails due to these `null` values, returning HTTP `400` with `error: "VisitFlowValidationError"`.
4. **Extra Property `source`**:
   The frontend also sends `source: "voice"`. The current `visitFlowRequestSchema` does not declare `source`. Standard Zod objects strip undeclared properties, so `source` is currently ignored without breaking validation. Adding `source: z.string().optional()` to the schema makes it explicit.
5. **Header Compatibility**:
   The frontend calls `fetchWithHandling` with `auth.denteClinicalReadHeaders({ "Content-Type": "application/json" })`. This sends `x-dente-admin-secret` and `x-dente-clinic-token` headers, satisfying `requireClinicalMutationAccess` and `requireResolvedOrganizationId` in `apps/api/src/routes/ai.ts`.

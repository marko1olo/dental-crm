# Механизм: подпись инструмента в коммите больше не проходит

Установлено ведущим 2026-07-28, после того как в конституции появилось правило
(`.agents/AGENTS.md`, «NO TOOL ATTRIBUTION IN THE COMMIT, EVER») и измерение: правило
нарушено **220 раз**, 96 из них в последних 200 коммитах.

## Почему записанного правила не хватило

Строку `Co-Authored-By: Claude <noreply@anthropic.com>` дописывает инструментарий, а не
человек. Автор сообщения её не пишет и в готовом коммите не видит. Правило, которое
нарушается автоматически, документом не лечится: за сутки его нарушили ещё почти сотню
раз. Проверено измерением, а не предположением:

```
git log --format="%H %b" | grep -ci "Co-Authored-By: Claude\|Generated with.*Claude"
221
```

## Что сделано

Добавлен хук `commit-msg`. Он лежит в глобальной папке хуков, на которую уже указывает
`core.hooksPath` этого репозитория:

```
C:/Users/Admin/.git-hooks/commit-msg
```

Хук отвергает коммит, если в сообщении есть `co-authored-by`, адрес `@anthropic.com`,
строка вида «Generated with …» с именем инструмента, или значок робота. Отказ выводится
по-русски и говорит, что именно найдено, в какой строке и что делать.

Строки-комментарии git (начинающиеся с `#`) из проверки исключены: шаблон, упомянутый в
комментарии, нарушением не считается.

## Чем доказано, что хук работает

Проверены ОБА направления — проверка, которая не умеет отвергнуть, ничего не охраняет:

| вход | ожидание | факт |
|---|---|---|
| сообщение с `Co-Authored-By: Claude <noreply@anthropic.com>` | код 1, отказ с объяснением | код 1, найдено «3:Co-Authored-By: …» |
| обычное человеческое сообщение | код 0, коммит проходит | код 0 |

Плюс сам коммит, которым добавлен этот файл, прошёл через хук — то есть положительный
путь проверен не только вызовом скрипта, но и настоящим `git commit`.

## Границы и как отменить

- Хук читает ТОЛЬКО сообщение текущего коммита. Историю не переписывает и файлы не трогает.
- Папка хуков глобальная, то есть проверка действует во всех репозиториях этой машины.
  Это соответствует смыслу правила: требование владельца относится к его коммитам, а не к
  одному проекту.
- Отмена — удаление одного файла `C:/Users/Admin/.git-hooks/commit-msg`. Ничего больше
  восстанавливать не нужно.
- Существующий гейт `pre-commit` (gitleaks и Biome) НЕ ТРОНУТ: добавлен отдельный файл,
  чтобы не вмешиваться в чужую проверку.

## Что НЕ сделано и почему

**Прошлые 220 коммитов не переписаны.** В дереве непрерывно работает второй инженер и
субагенты; перезапись истории уничтожила бы их работу и сломала бы ссылки в отчётах,
которые уже ссылаются на хэши. Конституция фиксирует то же решение. Цена нарушения
остаётся в истории навсегда — единственное доступное лекарство в том, чтобы оно
прекратилось, и теперь за этим следит механизм.

## Собственная ошибка, поправленная сразу

Первая редакция хука искала запрещённую подстроку ГДЕ УГОДНО в сообщении — и отвергла
коммит, которым добавлялся этот самый файл: в сообщении запрещённая строка была
процитирована как пример. Сторож потребовал стереть единственный текст, объясняющий,
зачем он нужен.

Это та же болезнь, которую в этот же день лечили у стража оформления рабочих панелей: он
находил зашитые цвета внутри комментария, который рассказывал, как эти цвета убрали. Вывод
один и тот же: сторож, краснеющий на объяснении, будет выключен, и участок останется без
охраны вовсе.

Исправлено привязкой к НАЧАЛУ строки. Запрещён трейлер — отдельная строка вида
`Co-Authored-By: …`, `Generated with …`, `Signed-off-by: …@anthropic.com` или строка,
начинающаяся значком робота. Упоминание той же строки внутри предложения нарушением не
считается.

Проверены четыре случая, а не два:

| вход | ожидание | факт |
|---|---|---|
| трейлер `Co-Authored-By: Claude <…@anthropic.com>` | код 1 | код 1 |
| трейлер `Generated with Claude Code` | код 1 | код 1 |
| та же строка, процитированная внутри предложения | код 0 | код 0 |
| обычное сообщение о правке кассы | код 0 | код 0 |

feat(карточка пациента): журнал звонков и сообщений считался по таблице, в которую никто не пишет

Карточка пациента на обоих экранах всегда отвечала «Записи звонков и сообщений
с пациентом отсутствуют». Причина не в интерфейсе: маршрут читал таблицу
patient_communication_timelines, у которой во всём apps/api/src нет ни одного
писателя — только объявление схемы и модуль чтения. Панель была гарантированно
пустой в любой клинике, сколько бы та ни звонила и ни писала пациенту.

Чем это плохо для клиники. «Ему уже звонили? он ответил? предупредили о
переносе?» — самый частый вопрос регистратуры про конкретного человека. Без
ответа администратор либо звонит второй раз (пациент раздражается), либо не
звонит вовсе, считая, что коллега отработал (пациент не приходит). Хуже того:
у мёртвой таблицы нет колонки patient_id вообще, связь с картой делалась
сравнением ФИО строкой. Появись у неё писатель — два тёзки получили бы общую
переписку, а смена фамилии после свадьбы оторвала бы историю от карточки.

Теперь GET /api/patients/:patientId/communication-timelines отдаёт расчёт по
живому источнику communication_events: patient_id uuid NOT NULL со ссылкой на
patients.id и пять настоящих писателей по пяти каналам (communications.ts,
messengerIngestion.ts, telephony.ts, vk.ts, whatsapp.ts).

Отдельно закрыты три подмены, каждая дороже пустого экрана:
- отсутствие карты отвечает 404, а не пустым журналом: пустой журнал оператор
  читает как «с человеком не связывались»;
- отказ базы отвечает 500 с причиной и действием, а не пустым списком;
- нечитаемый идентификатор в адресе («undefined» из интерфейса) отвечает
  «Пациент не выбран», а не ошибкой разбора типа uuid из PostgreSQL.

Итоги (всего обращений, период, число задач needs_call) считаются по всему
журналу отдельным запросом, а не по показанным строкам: иначе счётчик соврал бы
у каждого, у кого обращений больше лимита.

Ссылки на таблицу внутри sql`` пишутся как ${communicationEvents}."status" — на
голом ${table.column} в этом проекте дважды теряли данные: в подзапросе имя
связывается с внутренней таблицей, получается a.patient_id = a.id, валидный
SQL, всегда ложь, пустой экран без ошибки. Сгенерированный SQL проверяется
тестом по тексту, а не глазами.

# Экран выплат врачам: сделан достижимым и понятным

HEAD до коммита: `8a2f2e858`.

## Сначала — проверка, есть ли что монтировать

Маршрут `GET /api/billing/payouts` **существует**. Проверено двумя способами, не одним:

1. Статически: `apps/api/src/routes/billing.ts:276` — `app.get("/api/billing/payouts", …)`.
2. Живым запросом к поднятому серверу (`API_PORT=4188`), с контрольным опытом на
   заведомо отсутствующий адрес:

```
GET /api/billing/payouts                     -> HTTP 401 {"error":"AuthRequired","message":"Требуется авторизация рабочего кабинета клиники: расчёт выплат считается по одной клинике."}
GET /api/billing/definitely-not-a-route      -> HTTP 404 {"message":"Route GET:/api/billing/definitely-not-a-route not found"}
```

401 против 404 на том же сервере — маршрут обслуживается, а не отсутствует. Серверный
этап дошёл, фасад монтировать было на что.

Форма ответа снята с живого сервера, а не выведена из типов: 20 полей строки и 10 полей
итогов, `scope: "all" | "own"`.

## Что было не так и почему это было плохо для клиники

`apps/web/src/pages/DoctorPayoutDashboard.tsx` до правки:

1. **Экран не видел никто.** Его рендерил только `pages/FinancialDashboard.tsx`, которого
   не импортировал ни один файл. Владелец считал зарплату врачей в тетради, хотя касса
   в базе есть.
2. **Читал поля, которых сервер не отдаёт**: `revenue`, `netPayout`, `commissionRate`,
   `date` — вместо `revenueRub`, `payoutRub`, `commissionPct`. Строки `Number(item.revenue ?? 0)`
   (:33-36) на живом ответе напечатали бы **ноль в каждой денежной колонке молча**, без
   единой ошибки: 44 000 ₽ кассы врача превратились бы в 0 ₽.
3. **Отсутствующая ставка и ставка «ноль процентов» выглядели одинаково**: `commissionRate ?? 0`
   печатал «0 %». Это читается как «врач работает бесплатно», а не как «процент не задан».
4. **Отказ выдавался за пустоту.** Любой успешный ответ без массива `payouts` уходил в
   `setPayouts([])` (:40-42) и рисовал «Записи отсутствуют». Пустая таблица на месте
   зарплаты — самая дорогая ошибка в этом продукте.
5. Техническая строка «Ошибка загрузки выплат: HTTP 404» (:62) — человек за стойкой не
   знает, что такое HTTP 404, и не знает, что делать.
6. Посылал `denteAdminSecretRequestHeaders()` (:23) — один секрет периметра. Маршрут
   выплат требует **опознанного сотрудника**, потому что зарплата бывает «своя» и «чужая».

## ДОЛГИ

1. **УТЕЧКА, СЕРВЕРНАЯ ЧАСТЬ, НУЖНО РЕШЕНИЕ ВЕДУЩЕГО.** При `scope: "own"` врач получает в
   `totals` кассу **всей клиники**. Наблюдено живым запросом: врач d005 со своей кассой
   23 400 ₽ получает `totals.revenueRub = 67400`, `paymentCount = 8`. Причина:
   `buildPeriodRevenueQuery` (`apps/api/src/services/finance/doctorPayouts.ts:568-593`) не
   применяет `scope.onlyDoctorUserId`, хотя `scope` ему передан. Затронуты `revenueRub`,
   `paymentCount`, `attributableRevenueRub`, `unattributedRevenueRub`; суммы, производные от
   строк (`payoutRub`, `accruedRub`, `withheldMaterialRub`), отфильтрованы верно.
   **На экране закрыто**: в режиме «свои» касса складывается по видимым строкам, и 67 400 ₽
   врачу не показывается (проверено). **Но в ответе API число остаётся** — врач увидит его в
   сетевой панели браузера. Чинить надо в запросе. Файл только что закоммитил другой
   исполнитель, у него 13 тестов и прогон на 58 сверок; правку не делал, чтобы не ломать чужой
   гейт на ходу.
2. **`scripts/smoke-dental-persistence-routes-source.mjs` уже был сломан до меня** и остаётся
   сломанным: он читает `apps/web/src/pages/InvoiceSplitPaymentModal.tsx` и

## Требование, общее для всех целей

**1. Сторож обязан уметь покраснеть.** По каждой цели: временно внести в рабочий код настоящий
дефект того класса, показать красный вывод, вернуть код, показать зелёный. Оба вывода — в отчёт.
Без этого цель не сдана.

**2. Сторож не должен краснеть на объяснении, и это ИЗМЕРЕНО, а не опасение.** Наивный
текстовый шаблон `catch[\s\S]{0,200}?inMemory` по `apps/api/src/db/*Query.ts` даёт **3
совпадения**, из которых **2 — пояснительные комментарии** (докстринг
`patientArchiveReasonsAndBlacklistsQuery.ts:17-42` и разбор
`patientsQuery.ts:93-101`, оба рассказывают, как подмену УБРАЛИ). После вырезания комментариев
остаётся **1 совпадение — и это настоящее живое нарушение** `patientsQuery.ts:81`. То есть
67 % срабатываний наивного сторожа — наказание за документацию.

Поэтому у каждого сторожа, читающего исходники, обязательны: вырезание комментариев до
сопоставления, привязка шаблона к началу строки/AST, и САМОПРОВЕРКА в обе стороны —
«заведомый образец найден» И «цитата в комментарии пропущена». Готовый образец такой
самопроверки уже есть в дереве: `apps/web/src/tests/operationsPanelsStyling.test.ts:71-93`
(`stripComments` + четыре встречных утверждения). Его и копировать, второй раз изобретать не надо.

**Замер по зоне:** из 22 сторожей, читающих исходники через `readFileSync`, у **17 нет ни
вырезания комментариев, ни самопроверки**. Среди них все три цели ниже.

## Цель 1. `noFabricatedDataFallback.test.ts` пропускает класс «catch отдаёт подставное значение», и через эту дырку выдуманное ФИО попадает в ЮРИДИЧЕСКИЙ документ

**Файл сторожа:** `apps/api/src/tests/noFabricatedDataFallback.test.ts:69-98`
**Живые нарушители (вне моей зоны — правка их отдельным долгом, см. цель 6):**
`apps/api/src/db/patientsQuery.ts:81`, `apps/api/src/db/pricelistQuery.ts:165`,
`apps/api/src/db/patientArchiveReasonsAndBlacklistsQuery.ts:122`

**Что именно плохо для клиники.** `getPatientByIdFromDb` (`patientsQuery.ts:73-83`) при сбое
базы возвращает пациента из `sampleData.ts` — демонстрационного массива с ФИО
«Петров Иван Иванович», «Иванова Марина Сергеевна», **не отфильтрованного по организации**.
Эта функция кормит не экранчик, а изготовление документов: `routes/documents/create.ts:77`,
`issue.ts:74`, `pdf.ts:159`, `html.ts:74`, `taxXml.ts:66`, `void.ts`, `auditFacts.ts:73`, плюс
`routes/ai.ts:98,146` и `routes/imaging.ts:6580`. Один сбой базы — и согласие на медицинское
вмешательство, справка для НДФЛ или выписка печатается с именем чужого человека. Это подлог в
документе, а не «пустой экран».

Тот же класс: `pricelistQuery.ts:165` при сбое отдаёт зашитый идентификатор организации
`00000000-0000-0000-0000-000000000001` — то есть прайс и документы уедут в чужую клинику;
`patientArchiveReasonsAndBlacklistsQuery.ts:122` целиком проглатывает отказ записи в чёрный
список: администратор видит успех, строки в базе нет, после перезапуска запрет исчез.

**Почему сторож молчит.** Он судит по ТЕКСТУ, а не по форме:
* `:73` `/DB Fallback/` — такой строки в нарушителях нет;
* `:76` `/if \(rows && rows\.length > 0\) return rows;/` — точная строка исходника, ни у одного
  нарушителя её нет;
* `:89` `/catch \([^)]*\) \{\s*\n\s*console\.warn/` — требует `console.warn` СРАЗУ после скобки,
  и обходится одной строкой комментария: так `db/aiQuery.ts:132` под неё не попадает;
* проверки «catch возвращает значение» нет ни одной;
* обход каталога `:46-50` нерекурсивный и только по маске `*Query.ts` — `db/tests/`,
  `db/domainStateHydration.ts`, `db/patientsSchema.ts`, `db/communicationsSchema.ts` вне переписи.

Самое показательное: `getPatientsFromDb` (список, `:86-105`) эту подмену уже ПОЧИНИЛИ, с
подробным комментарием на девять строк. Его близнеца `getPatientByIdFromDb` двумя функциями
выше не тронули, и сторож не показал на него пальцем ни до, ни после.

**Как доказать.**
1. Замер класса (мой, воспроизводимый): AST-перепись `catch` без `throw` по
   `apps/api/src/db/*Query.ts` даёт **5 модулей** — `aiQuery.ts:132` (осознанно, есть
   объяснение), `clinicalQuery.ts:30` (это `JSON.parse`, а не база — ложное срабатывание,
   сторож обязан его НЕ считать), `patientArchiveReasonsAndBlacklistsQuery.ts:122`,
   `patientsQuery.ts:81`, `pricelistQuery.ts:165`.
2. Красный: временно вернуть в `patientsQuery.ts` строку
   `catch { return inMemoryPatients.find(...) }` в любую другую функцию → `npx tsx --test
   src/tests/noFabricatedDataFallback.test.ts` обязан упасть с текстом, называющим файл и строку.
3. Зелёный после возврата кода.
4. Самопроверка внутри теста: фикстура с проглатывающим `catch` находится; фикстура, где та же
   конструкция стоит в комментарии, — НЕ находится.

**Как чинить, чтобы ловило.** Судить по AST, а не по тексту. `typescript` в дереве есть и
работает (`scripts/census-hollow-query-modules.mjs` уже строит AST). Правило: `catch`, в теле
которого нет `throw`, а есть `return`, при том что `try` обращается к базе (`db.` или
`await …InDb/…FromDb`) — нарушение. `catch` вокруг `JSON.parse` под правило не попадает по
ФОРМЕ (в `try` нет обращения к базе), а не по списку исключений. Обход `db/**` сделать
рекурсивным и по всем `.ts`, а не по маске имени.

**Про допуск существующих нарушений.** Починка сторожа немедленно покраснеет на трёх файлах в
`apps/api/src/db/**` — это вне моей зоны. Допускается ровно один способ остаться зелёным:
явный список-храповик с ТОЧНЫМ числом (без запаса) и ПРИЧИНОЙ у каждой строки, по образцу
`DECLARED_UNMOUNTED` из `apps/web/src/tests/panelsAreMounted.test.ts:405-440`, где причина
короче 120 символов сама валит тест. Молча ослаблять правило запрещено.

**Вердикт: fix.**

## РАЗБОР ВЕДУЩЕГО (02:2x): два оставшихся адреса — ЛОЖНЫЕ ТРЕВОГИ, а не дефекты продукта

Храповик адресов после переписывания сведения сходится (было 4 падения из 5, стало 1 из 3), но
красным его держат два адреса, и оба — промахи самой проверки. Разбор ведущего, чтобы он не
переоткрывался с нуля.

### 1. `/api/communications/campaigns/SEGMENT/SEGMENT`

Клиент зовёт `` `/api/communications/campaigns/${campaignId}/${action}` ``
(`components/communications/CampaignPanel.tsx:254`), где `action` — `"launch"` либо `"cancel"`.
Сервер обслуживает ОБА: `communicationsOutbox.ts:810` (`:campaignId/launch`) и `:831`
(`:campaignId/cancel`). Проверено чтением обоих файлов.

Промах в сведении: ВТОРАЯ подстановка тоже становится `SEGMENT`, и сравнение `SEGMENT` против
литерала `launch` не проходит. Прежняя редакция `isServed` это умела — там сегменты считались
совместимыми, если равны ЛИБО хотя бы один из них подстановка. Проверь, сохранилось ли это
правило для нового маркера: если сравнение стало строгим, любой адрес с двумя подстановками
подряд будет краснеть вечно.

Семантика правильная и она же безопасная: подстановка означает «значение статически неизвестно»,
поэтому она обязана совпадать и с параметром маршрута, и с литералом. Иначе страж утверждает
«такого адреса нет» про адрес, которого он просто не смог разобрать, — то есть выдумывает.

Отдельно: второй инженер ЗНАЛ про эту слепоту и написал о ней в комментарии
(`CampaignPanel.tsx:244-253`). Комментарий верен по сути и должен остаться.

### 2. `/api/settings/staff*`

Адрес взят из JSDoc-блока `components/settings/settingsInviteRoles.ts:172-179`: там объясняется,
что маршруты семейства `/api/settings/staff*` отвечают на отказ телом `{error, message}`.
Звёздочка — знак «семейство», а не путь. Никакого вызова там нет.

Прежнее вырезание комментариев регулярным выражением этот блок УБИРАЛО — измерено ведущим на
живом файле до переписывания. Значит новое построчное вырезание на JSDoc-блоке этот случай
потеряло. Проверь именно `/** ... */`, а не `/* ... */`.

Это ровно та болезнь, которую сам страж и лечит: он краснеет на ОБЪЯСНЕНИИ. В этом дереве она
случалась уже трижды (страж оформления на комментарии про токены темы, хук подписи инструмента
на цитате запрещённой строки, и вот здесь). Самопроверка вырезания обязана содержать случай
`/** адрес в JSDoc */` как отдельный образец.

### Требование ведущего к закрытию участка

Оба случая закрываются починкой СТРАЖА, а не правкой продукта и не строкой в списке долга.
Внесение верного адреса в `KNOWN_MISSING` было бы враньём: адрес обслуживается, и запись в
списке долга это скрывает. Страж, красящий верный код, будет выключен — и тогда он не поймает
ни одного настоящего дефекта.

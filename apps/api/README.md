## 🏗️ Ключевые архитектурные инварианты

1. **Fastify 5.3+ High Performance Core**:
   - Высокопроизводительный асинхронный HTTP-сервер на базе Node.js (ESM).
   - Подключение плагинов безопасности `@fastify/helmet`, `@fastify/cors`, `@fastify/rate-limit`.
   - Полнодуплексный брокер реального времени `@fastify/websocket` (`/api/ws/schedule`).
2. **Нативный PostgreSQL 18.4 TCP (Никакого PGlite!)**:
   - Работает строго по TCP через пул соединений `pg.Pool` на `127.0.0.1:5432`.
   - Рабочая база данных: `dental_crm`.
   - Директория данных на хосте: `.data/pg18` в корне репозитория (папка `apps/api/dente-db` является устаревшим PGlite-артефактом с PID `-42` и не используется).
   - Бинарные файлы СУБД: `node_modules/@embedded-postgres/windows-x64/native/bin/` (`postgres.exe`, `initdb.exe`, `pg_ctl.exe`).
3. **Модульная схема Drizzle ORM (20 файлов, 203 таблицы)**:
   - Монолитный файл схемы разделен на **18 предметных модулей** в `apps/api/src/db/schema/*.ts` + `_common.ts` + `index.ts`.
   - `apps/api/src/db/schema.ts` — 7-строчный прокси обратной совместимости, реэкспортирующий `src/db/schema/index.ts`.
4. **Строгая изоляция организаций (PostgreSQL Row-Level Security — RLS)**:
   - Включена и принудительно активирована (`FORCE ROW LEVEL SECURITY`) на 147 таблицах.
   - Политика `tenant_isolation` фильтрует строки по `app.current_tenant = organizationId` через `AsyncLocalStorage` (`withTenantCtx`).
   - Механизм fail-closed: без контекста арендатора запросы возвращают пустой набор.
5. **Финансовая и медицинская математика**:
   - Все денежные суммы ведутся **строго в целочисленных копейках** (тип `integer` / `bigint`).
   - Запрещены операции с плавающей запятой (`float`/`double`) в биллинге, зарплатах и чеках.
   - Числовые поля `numeric` парсятся через `registerMoneyTypeParsers()` до инициализации пула.
6. **Мандат 8e (Автономия врача)**:
   - Запрещены блокировки кнопок оформления приема из-за второстепенных полей.
   - Врач имеет право на скидки до 100% и исправление дневников с версионным аудитом.
   - Истечение 30 дней плана лечения не блокирует наряды ЗТЛ, оказание услуг или оплату.
7. **Мандат 8n: Приоритет №1 — Соло-врач и небольшая клиника 1–3 кресла (Zero Dead-Ends)**:
   - До больших сетей нам ещё расти и расти! Первичный фокус всех роутов, валидаторов и транзакций — соло-врач на аренде и компактная клиника.
   - Касса 54-ФЗ не требует ИНН с физических лиц при оплате картой или наличными.
   - Создание записи в расписании не требует обязательного ассистента.
   - Списание материалов пакетом в 1 клик без складских комиссий из 3 человек.
   - Мягкий овердрафт склада вместо блокировки экстренных приёмов.
   - Закон отсутствия тупиков (Zero Dead-Ends): бэкенд никогда не выбрасывает фатальные блокировки из-за отсутствия enterprise-интеграций. Сетевые модули закладываются «на вырост» без тупиков.

## 🚀 Система миграций (`apps/api/src/scripts/migrate.ts`)

В проекте используется **собственный надежный раннер SQL-миграций** `apps/api/src/scripts/migrate.ts`:
* Считывает SQL-файлы из директории `apps/api/drizzle/*.sql` по возрастанию порядкового номера.
* Применяет каждый файл в **изолированной транзакции**.
* Фиксирует факт применения и контрольную сумму **SHA-256** в системной таблице **`_dente_migrations`**.
* Поддерживает маркер `-- no-transaction` в первой строке для команд создания индексов `CREATE INDEX CONCURRENTLY` (PostgreSQL запрещает выполнять их внутри транзакционного блока).
* Разделение инструкций выполняется через модуль `src/scripts/sqlStatements.ts` с полным учетом комментариев и dollar-quoting (`$$`).

### Команды управления миграциями

```bash
# Применить все недостающие миграции к целевой базе DATABASE_URL
npm run db:migrate -w @dental/api

# Холостой прогон (dry-run): показывает список файлов без применения
npm run db:migrate:check -w @dental/api

# Режим бейслайна: отметить существующие файлы применёнными без выполнения DDL
npm run db:migrate:baseline -w @dental/api

# Строгий режим CI: завершается с ошибкой при изменении контрольной суммы
npm run db:migrate:strict -w @dental/api
```

### Защита от деструктивного сброса (`apps/api/src/scripts/migrateStateToDb.ts`)

Скрипт `npm run db:reset-seed` защищен **многоуровневым предохранителем**:
1. Выполняется строго в рамках одной транзакции с установкой `app.current_tenant`.
2. Если в таблицах арендатора есть данные, скрипт требует явную переменную окружения:
   ```bash
   DENTAL_ALLOW_DESTRUCTIVE_DB_RESET="YES"
   ```
3. При `NODE_ENV=production` выполнение скрипта **заблокировано безусловно**, независимо от наличия флага.

## 🌐 WebSocket-шлюз реального времени (`/api/ws/schedule`)

Реализован на базе `@fastify/websocket` в модуле `apps/api/src/routes/websocket.ts` и сервисе `src/services/websocketBroker.ts`.

### Авторизация и безопасность
* В соответствии с требованиями безопасности токены сессии **никогда не передаются в строке запроса (query params)**, чтобы исключить утечку в логи доступа, историю браузера и заголовок Referer.
* После установки TCP-соединения клиент обязан в течение **10 секунд (`AUTH_TIMEOUT_MS`)** прислать первый JSON-кадр авторизации:
  ```json
  {
    "type": "AUTH",
    "clinicToken": "...",
    "staffToken": "..."
  }
  ```
* При отсутствии кадра или невалидных токенах сервер закрывает соединение со специальными кодами `4408` (Auth Timeout) или `4401` (Unauthorized).

### Диспетчеризируемые события (`wsBroker`)
* `TELEPHONY_INCOMING_CALL` — Всплывающая капсула входящего звонка в едином тулбаре десктопа.
* `SCHEDULE_APPOINTMENT_CHANGE` — Живое перемещение, перенос или изменение статуса приема в сетке.
* `VISIT_DIARY_AUTOSAVE` — Синхронизация статуса автосохранения протокола 043/у.
* `ODONTOGRAM_STATE_CHANGED` — Мгновенное обновление формулы зубов при работе терапевта/хирурга.
* `LAB_ORDER_STATUS` — Уведомление о готовности ортопедической работы из лаборатории (ЗТЛ).
* `FINANCE_TRANSACTION` — Обновление баланса пациента и общего семейного депозита.
* `CHAT_MESSAGE_RECEIVED` — Поступление сообщения в омниканальный инбокс (WhatsApp/Telegram/VK).

## 🔌 Интеграционные шлюзы РФ

### 1. Онлайн-кассы 54-ФЗ и ФФД 1.2 (`apps/api/src/routes/fiscal/`, `billing.ts`)
* Прямое взаимодействие с кассовыми аппаратами (Атол, Штрих-М, Веб-касса).
* Обязательная передача тегов номенклатуры медицинских услуг:
  - Тег `1212` — признак предмета расчета (услуга).
  - Тег `2108` — код номенклатуры медицинских услуг по Приказу Минздрава 804н.
* **Запрет на требование ИНН с физических лиц**: при наличной оплате и оплате банковской картой физическими лицами ИНН не запрашивается.
* Поддержка комбинированной оплаты (наличные + эквайринг + аванс/бонусы) с копеечной точностью.
* Автоматическая очередь чеков `fiscalReceiptQueue` с повторными попытками при сбоях связи с ОФД.

### 2. ЕГИСЗ РЭМД и N3.Health (`apps/api/src/routes/egisz.ts`, `services/egisz/`)
* Формирование структурированных электронных медицинских документов (СЭМД) по стандарту **HL7 CDA R3**.
* Подписание документов усиленной квалифицированной электронной подписью (УКЭП) врача и клиники через КриптоПро ЭЦП.
* Фоновый воркер `EgiszQueueWorker.ts` с экспоненциальной задержкой повторов при сбоях регионального шлюза.

### 3. МДЛП «Честный ЗНАК» (`apps/api/src/routes/mdlp.ts`, `services/mdlp/`)
* Сканирование 2D-кодов DataMatrix лекарственных препаратов (анестетики, антибиотики).
* Регистрация вывода из оборота по причине «для оказания медицинской помощи».
* Синхронизация партий с FEFO-складом и списание карпул анестетиков в 1 клик согласно СанПиН 3.3686-21.

### 4. Telegram Bot API и Мессенджеры (`apps/api/src/routes/telegram.ts`, `whatsapp.ts`, `vk.ts`)
* Поддержка двух режимов: общий бот DENTE и собственный бот клиники.
* Авторизация пациентов через одноразовые коды привязки (`telegramLinkCodes`).
* Строгий режим защиты врачебной тайны (152-ФЗ): сообщения по умолчанию не содержат персональных медицинских данных (PHI-safe).
* Вебхуки WhatsApp Cloud API и VK MAX с идемпотентной дедупликацией входящих событий.

## ⚙️ Переменные окружения (`.env`)

| Переменная | Обязательна | Назначение | Пример значения |

| `PORT` | Нет | Порт входящих HTTP соединений (по умолчанию 3000) | `3000` |
| `HOST` | Нет | Хост привязки сокета (по умолчанию 127.0.0.1) | `127.0.0.1` |

| `TELEGRAM_BOT_TOKEN` | Нет | Токен бота клиники в Telegram | `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ` |
| `YANDEX_SPEECHKIT_API_KEY` | Нет | Ключ API распознавания речи диктовки врача | `AQVN...` |

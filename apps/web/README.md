## 🏗️ Архитектурные инварианты фронтенда

### 1. Трехуровневая модель интерфейса (3-Tier Clinical Architecture)
* **TIER 1 (Hot Path / Основная рабочая зона — 0 кликов, всегда на экране):**
  - Интерактивная зубная формула FDI (11..48 adult, 51..85 pediatric), высота ≥ 140–160px.
  - Мгновенные статусы зуба в 1 клик (Кариес, Пульпит, Пломба, Коронка, Удален, Здоров).
  - Итоговая сумма к оплате в ₽ + 1-клик выбор способа расчета по 54-ФЗ.
  - Дневник Формы 043/у с локальным автосохранением в IndexedDB (debounce 150–300 мс).
  - Баннер критических противопоказаний (аллергия, геморрагии, соматика) — всегда на виду без всплывающих окон.
* **TIER 2 (Warm Context / Контекстные панели сущности — 1 клик):**
  - Раскладка зуба по 5 анатомическим поверхностям (MOD).
  - Калькулятор анестезии по массе тела пациента.
  - Привязка крафт-пакета и автоклава СанПиН 3.3686-21.
  - Семейный баланс и списание бонусных баллов.
  - Мгновенный предпросмотр снимка визиографа (200x200px), привязанного к активному зубу.
* **TIER 3 (Cold Backoffice / Специализированные кабинеты — полноэкранный режим / студия):**
  - 3D DICOM / CBCT Multi-Planar Reconstruction (MPR) просмотрщик на базе WebWorker.
  - Выгрузка ЕГИСЗ РЭМД CDA R3 XML с подписанием УКЭП через КриптоПро ЭЦП Browser plug-in.
  - Расчет зарплатной ведомости врачей Т-51 и табеля Т-13.
  - Формирование справок 13% НДФЛ по форме ФНС КНД 1151156.
  - Аудит склада Честный Знак (МДЛП).

### 2. Закон Анти-Матрёшки (Anti-Matryoshka Law)
- Глубина модальных окон СТРОГО ≤ 1. Модалки поверх модалок категорически запрещены.
- Карточки внутри карточек запрещены: единая тональная подложка (`var(--paper)` → `var(--paper-strong)`) без многослойных рамок.

### 3. Мандат 8e (Автономия врача и персонала)
- **Никаких disabled кнопок без причины**: Кнопки «Сохранить», «Завершить приём», «Добавить услугу», «Печать» никогда не блокируются серым цветом из-за незаполненных второстепенных полей.
- **Физиологическая норма по умолчанию**: Анамнез и осмотр заполняются нормальными значениями в 1 клик («Соматически здоров / норма»). Врач фиксирует только патологию.
- **Печать в любой момент**: Форма 043/у, согласия и сметы печатаются мгновенно (со штампом «ЧЕРНОВИК» до закрытия приёма, «ПОДПИСАНО ВРАЧОМ» после).
- **Свобода скидок врача**: Врач имеет право применить скидку (вплоть до 100% на переделки и персонал) без ввода мастер-паролей. Истечение 30 дней плана лечения не блокирует наряды ЗТЛ и оплату.
- **Касса 54-ФЗ без палок в колёса**: Запрещено требовать ИНН с физлиц при оплате наличными или картой. Комбинированная оплата (нал + карта + аванс) принимается в 1 клик.
- **Молниеносный рентген**: Снимок визиографа открывается < 50 мс в полном разрешении датчика без зависаний на нейросети.

### 4. Мандат 8n (Приоритет №1: Соло-врач и небольшая клиника 1–3 кресла, Zero Dead-Ends)
> 🎯 **СТРАТЕГИЧЕСКИЙ ПРИОРИТЕТ №1: СОЛО-ВРАЧ И НЕБОЛЬШАЯ КЛИНИКА 1–3 КРЕСЛА. ДО БОЛЬШИХ СЕТЕЙ НАМ ЕЩЁ РАСТИ И РАСТИ!**
- Соло-врач на аренде совмещает все роли: запись за 5 секунд без обязательного ассистента, 1-клик касса 54-ФЗ без ИНН физлиц, 1-клик списание анестетика клиническим пакетом, печать договоров со строками `_____` без 403 Forbidden.
- Закон отсутствия тупиков (Zero Dead-Ends): программа никогда не блокирует клинический процесс тупиковыми ошибками. Сетевые модули закладываются «на вырост», не загромождая рабочее место соло-врача.

## 🧠 Архитектура Состояния (`useAppLogic.tsx`)

Центральный хук управления состоянием `useAppLogic.tsx` декомпозирован на **27 модульных доменных хуков** в `apps/web/src/hooks/domains/`:
- `useScheduleLogic.ts` — состояние сетки расписания и перемещения визитов.
- `useVisitLogic.ts` — активный приём, SOAP дневник, зубная формула.
- `useBillingLogic.ts` — кассовые операции 54-ФЗ, эквайринг, наряды.
- `usePatientLogic.ts` — реестр пациентов, семейные группы, прикрепления.
- `useDocumentStore.ts` — генерация и печать медицинских бланков.
- Защитный гейт `npm run check:stub-overrides` непрерывно проверяет 828 свойств возвращаемого объекта на отсутствие дублирования и затенения свойств.

## 🎨 Стандарты дизайна и темы оформления

- **Строгий запрет на хардкод цветов**: Запрещены статические цвета (`#fff`, `#000`, `bg-white`). Используются исключительно CSS-переменные дизайн-системы:
  - `var(--paper)` — фон рабочей области.
  - `var(--paper-strong)` — фон модальных панелей и карточек первого уровня.
  - `var(--ink)` — основной контрастный цвет текста (WCAG AAA ≥ 4.5:1).
  - `var(--muted)` — цвет вспомогательного текста.
  - `var(--primary)` / `var(--primary-strong)` — акцентные медицинские тона.
- **Поддерживаемые темы**: Light, Dark, Ocean, Sakura, Emerald, Cyber X-Ray, Night, Warm Sand, Calm Teal, Contrast.
- **Валидация тем**: Любые изменения стилей проверяются запуском `npm run check:css-tokens`.

## 4. АРХИТЕКТУРНЫЙ ЭКЗОСКЕЛЕТ DENTALPIN: ПОЧЕМУ ИХ ИИ ФИЗИЧЕСКИ НЕ МОЖЕТ СОЗДАТЬ МОНОЛИТ

Вскрываем главный секрет DentalPin. Почему у них всё так чисто?  
Они создали архитектуру, в которой **у модели нет возможности согрешить**:

### 4.1. Архитектурный контракт плагина (`BaseModule` + `manifest`)
В DentalPin каждый домен (пациенты, расписание, зубы, склад, налоги) обязан лежать в `backend/app/modules/<name>/` и иметь стандартную структуру:
```
backend/app/modules/<name>/
├── __init__.py           # Наследник BaseModule с manifest
├── models.py             # SQLAlchemy 2.0 модели
├── router.py             # FastAPI роутер с ApiResponse[T]
├── service.py            # Чистый бизнес-слой (статические методы)
├── schemas.py            # Pydantic схемы валидации
├── tools.py              # Инструменты, доступные AI-агентам!
├── CLAUDE.md             # Локальная микро-инструкция (50-70 строк!)
├── CHANGELOG.md          # Локальный чейнджлог
├── migrations/versions/  # СВОЯ ИЗОЛИРОВАННАЯ ветка Alembic
└── frontend/             # Nuxt 4 слой (pages/, components/, composables/)
```

### 4.2. Жесткие архитектурные инварианты DentalPin:
1. **Изоляция модулей и `manifest.depends`:**
   Если модулю `treatment_plan` нужны данные из `patients`, модуль `patients` **обязан** быть объявлен в `manifest.depends`. Если его там нет — CI-скрипт `manifest-consistency` валит сборку на корню.
2. **Запрет прямых сервисных импортов через Event Bus:**
   Импортировать напрямую сервис другого модуля ЗАПРЕЩЕНО. Модули общаются исключительно через шину событий (`event_bus.publish("patient.created", {...})` и `event_bus.subscribe(...)`). Это разрывает циклические зависимости и делает невозможным создание God Context.
3. **Изолированные ветки Alembic (`branch_labels = ("<name>",)`):**
   У каждого модуля своя независимая ветка миграций. Миграция одного модуля не имеет права ссылаться на ревизию другого модуля. При удалении модуля его таблицы сносятся без повреждения остальной БД.
4. **Co-located Nuxt Layer:**
   Фронтенд модуля не свален в общую кучу `apps/web/src/components/`, а лежит прямо внутри модуля в папке `frontend/`. Nuxt автоматически подхватывает его как независимый слой через `modules.json`.
5. **Микро-контекст `CLAUDE.md` на 60 строк:**
   Когда AI приходит работать в модуль `odontogram`, он читает файл [`odontogram/CLAUDE.md`](file:///C:/Clinic_MVP/dental-crm/research/dentalpin/backend/app/modules/odontogram/CLAUDE.md), который занимает ровно **61 строку**! Там перечислено всё: эндпоинты, зависимости, события, права и 4 ключевых подводных камня (FDI numbering, JSONB surface state, idempotency).  
   Модели не нужно держать в голове 50 страниц общих инструкций — она видит хирургически точный скоуп.

## 8. КОНКРЕТНЫЙ ПЛАН РЕФОРМ: КАК ПРИВИТЬ НАШЕМУ РОЮ ТАКУЮ ЖЕ ЖЕЛЕЗНУЮ ДИСЦИПЛИНУ

Чтобы наша система перестала страдать от монолитов, фейковых песочниц и бесконечных распилов, необходимо перенести правила из текстовых промптов в **автоматические исполняемые инструменты**:

### Реформа №1: Жесткий линтер размера файлов (Hard 500 LOC Ceiling)
Ввести скрипт `scripts/check_file_limits.cjs` в git hook и CI:
- **Запрет на коммит:** Ни один новый файл в `apps/web/src/` или `apps/api/src/` не имеет права превышать **500 строк**.
- Если субагент пытается создать файл на 800 строк — коммит аварийно падает, заставляя субагента изначально декомпозировать код на подкомпоненты.

### Реформа №2: Автоматический охотник за песочницами (Anti-Sandbox CI Gate)
Ввести скрипт `scripts/check_no_sandboxes.cjs`:
- Любой файл, содержащий в имени `preview`, `sandbox` или лежащий вне стандартных роутов `apps/web/src/pages/`, блокирует коммит.
- Запрет на Puppeteer-тесты на файлах, отличных от `http://127.0.0.1:5173/`.

### Реформа №3: Локальные карточки модулей (`MODULE.md`) вместо 40 000 токенов
По образцу DentalPin (`CLAUDE.md` на 60 строк в каждой папке):
- В каждой доменной папке (`components/radiology/`, `components/visit/`, `services/dicom/`) создать краткий файл `MODULE.md` на 40–60 строк.
- Субагенту передавать контекст ТОЛЬКО его целевого модуля, освобождая 90% окна контекста для чистого кода и тестов.

### Реформа №4: Дробление скоупа субагентов (Закон атомарного шага)
Перестать ставить субагентам задачи уровня «Напиши весь модуль с нуля»:
- Шаг 1: Типы и контракты Zod/TS (< 100 LOC) + коммит.
- Шаг 2: Сервис Fastify + модульный тест (< 200 LOC) + коммит.
- Шаг 3: UI-компонент в реальном дереве CRM + визуальный пруф + коммит.

### Реформа №5: Сохранение клинического превосходства Dente
Не скатываться в примитивный CRUD DentalPin. Наша сила — в глубокой клинической начинке (DICOM, 3D, цефалометрия, СанПиН, касса, Telegram). Сохранить эту мощь, но упаковать её в такой же строгий модульный экзоскелет, как у них.

**Вердикт Инквизитора:** Презумпция брака подтверждена фактами. Модель в DentalPin не умнее нашей — она работает внутри несокрушимой архитектурной клетки и управляется человеком с точностью до 12 строк кода. Внедрение 5 реформ выше ликвидирует наше отставание по культуре коммитов навсегда.

## 1. АРХИТЕКТУРА ТРЕХУРОВНЕВОГО КАСКАДА (TIERED FAILOVER)

В условиях жестких лимитов провайдеров (Rate Limits) и возможных сбоев дата-центров StomChat использует отказоустойчивую трехуровневую систему генерации:

```
                            Запрос на генерацию от триажа
                                          │
                                          ▼
     ┌────────────────────────────────────────────────────────────────────────┐
     │ TIER 1: GOOGLE GEMINI (Основной провайдер)                             │
     │ - gemini-1.5-pro / gemini-2.0-flash-exp                                │
     │ - Пул из N ключей API с разделением квот                               │
     │ - Задержка (Cooldown) между обращениями: не менее 2-3 секунд           │
     └───────────────────────────────────┬────────────────────────────────────┘
                                         │ Ошибка: 429 / 500 / Timeout / Ban
                                         ▼
     ┌────────────────────────────────────────────────────────────────────────┐
     │ TIER 2: GROQ LLAMA-3.3-70B (Мгновенный высокоскоростной резерв)        │
     │ - llama-3.3-70b-versatile                                              │
     │ - Время отклика < 1.5 сек                                              │
     │ - Высокая устойчивость к нагрузкам                                     │
     └───────────────────────────────────┬────────────────────────────────────┘
                                         │ Ошибка или необходимость глубокого анализа
                                         ▼
     ┌────────────────────────────────────────────────────────────────────────┐
     │ TIER 3: DEEPSEEK REASONING (Клинический резонинг в сложных случаях)    │
     │ - deepseek-r1-distill-llama-70b                                        │
     │ - Очистка скрытых цепочек рассуждений strip_reasoning()                │
     └────────────────────────────────────────────────────────────────────────┘
```

## 2. ПРАВИЛА РОТАЦИИ КЛЮЧЕЙ И БЕЗОПАСНОСТИ API

### 2.1. Критическое правило безопасности (Защита от бана аккаунтов)
> **[FORBID]** Категорически запрещено тестировать или нагружать API-ключи (Groq, Gemini) спамом быстрых последовательных запросов без пауз. Массовые параллельные запросы вызывают автоматический бан аккаунта.
> Реализация: Все обращения к ключам одного провайдера разнесены во времени с обязательным кулдауном не менее 2–3 секунд (`_pace_vision_calls`, `_sleep_with_status`).

### 2.2. Пул ключей и учет сбоев (`gemini_client.py`)
- **`available_keys()`:** Возвращает список только «живых» ключей, у которых истек срок штрафного кулдауна.
- **`note_key_failure(key, error)`:**
  - Если ошибка `429 ResourceExhausted` — ключ помечается как исчерпанный на 60–300 секунд.
  - Если ошибка `403 / 400 API_KEY_INVALID` — ключ немедленно исключается из пула в черный список до перезапуска бота.
  - Если ошибка сети `503 / Timeout` — ключ получает короткий штраф 10–15 секунд.
- **`note_success(key)`:** Сбрасывает счетчик последовательных ошибок ключа и возвращает его в статус высоконадежного.

## 3. ОЧИСТКА ВЫХОДА РЕЗОНИНГ-МОДЕЛЕЙ (`strip_reasoning`)

Модели класса DeepSeek-R1 генерируют внутренние рассуждения внутри тегов `<think>...</think>`. Попадание этих размышлений в чат к врачам разрушает образ живого эксперта и перегружает сообщение.

В `gemini_client.py` встроен прецизионный парсер:
```python
def strip_reasoning(text: str) -> str:
    """
    Удаляет все блоки <think>...</think> и их незакрытые остатки,
    если генерация прервалась по таймауту или лимиту токенов.
    """
    if not text:
        return ""
    # Удаляем полные блоки рассуждений
    cleaned = re.sub(r"<think>.*?</think>", "", text, flags=re.DOTALL)
    # Если тег <think> открылся, но не закрылся (обрыв стриминга)
    if "<think>" in cleaned:
        cleaned = cleaned.split("<think>")[0]
    return cleaned.strip()
```

## 4. БЮДЖЕТИРОВАНИЕ ТОКЕНОВ И РЕГУЛИРОВАНИЕ ДЛИНЫ

В зависимости от формата обращения динамически подбираются параметры генерации:
1. Групповой ответ в чате: `max_tokens = 800`, `temperature = 0.3` (высокая строгость, лаконичность).
2. Личная консультация (PM): `max_tokens = 2500`, `temperature = 0.5` (глубокий разбор, пошаговый протокол).
3. Разрешение спора (бывший арбитраж): `max_tokens = 900`, `temperature = 0.2` (максимальная объективность, опора на EBM).
4. **Клинический рецензент (`check_response_quality`):** `max_tokens = 300`, `temperature = 0.0` (детерминированная оценка JSON).
